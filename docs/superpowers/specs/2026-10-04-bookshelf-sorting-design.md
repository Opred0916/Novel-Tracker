# Novel Tracker — 书架排序设计

日期：2026-10-04

## 目标与本轮边界

让书库变大、尤其是批量导入旧记录后，用户仍能按需要找到和回看小说。书架提供四种排序：“最近修改”“最近读完”“最近添加”“评分从高到低”。排序改变当前列表的展示顺序，不修改小说、阅读历史或摘记。

本轮只处理现有书架及其搜索／筛选结果。不增加分组、置顶、自定义顺序、书名拼音排序或批量编辑；不增加数据库字段、备份字段或联网服务。

## 排序交互

- 书架搜索框附近显示当前排序，例如“排序：最近修改”。轻点可展开四个互斥选项，选中后收起并更新列表；选项有明确的选中状态，屏幕阅读器能读出名称和状态。
- 首次打开书架默认“最近修改”，与现有行为一致。排序选择只保存在当前书架页面状态中；重新启动 App 后恢复默认。本轮不把设备偏好写进书库或备份。
- 关键词、阅读状态、作品类型和多个标签先决定哪些书出现在列表，再按所选规则排序。改变排序不清除搜索或筛选；筛选面板内的“重置筛选”只清除作品类型和标签，保留关键词、阅读状态与当前排序。关键词由搜索框内的 `×` 单独清除。筛选条件数量不计入排序。
- 空书架或搜索无结果时，排序入口仍可操作；原有空状态、搜索命中摘记／图片文字提示、进入详情与返回刷新行为保持可用。

## 四种顺序的准确含义

1. **最近修改**：按书籍已有 `updated_at` 从新到旧排列。这是默认顺序；导入当天新增的书会因此排在较早建档的书前。
2. **最近读完**：找每本书 `outcome='finished'` 的阅读历史中最新的有效 `ended_on`，按该日期从近到远排列。一本书二刷、三刷取最近一次；即使现在状态改为“在读”或“弃读”，过去确实读完的日期仍有效。弃读结束日不算“读完”。没有有效读完日期的书始终排在有日期的书后面；不使用书籍创建日、导入日、`legacyReadCount` 或当前“读完”状态猜测日期。
3. **最近添加**：按书籍已有 `created_at` 从新到旧排列。旧记录的导入时间是它加入本 App 的时间，不冒充原始阅读时间。
4. **评分从高到低**：按书籍现有总体评分 `rating_half_stars` 降序排列，半星档次保留；未评分的书排在已评分的书后面。评分是整本书当前的总体评分，不当作某一次阅读的历史评分；即使当前状态不是“读完”，已保留的评分仍参与排序。

每种规则的主排序值相同时，按 `updated_at` 从新到旧，再按稳定书籍 ID 升序；“最近修改”只需用 ID 解决时间相同的情况。没有有效读完日期的书、未评分的书也按这套次级规则排列，避免每次刷新顺序跳动。`ended_on` 必须是有效的四位 `YYYY-MM-DD` 日历日期；无效日期当作没有日期。

## 数据流与兼容

书架向现有搜索仓储传入排序枚举；搜索仓储保留原来的关键词、状态、作品类型、标签组合查询和命中依据，再对符合条件的书排序。只有选择“最近读完”时才额外读取已完成阅读的结束日期，一次读取并计算每本书的最新有效日期，避免为每张书卡单独查询阅读历史。排序比较放在独立的纯函数中，页面不自行重排数据库结果。

排序不写数据库，不需要迁移。旧书和旧导入记录仍可展示；没有读完日期或评分时按上述空值规则处理。搜索请求随排序变化重新执行，已有请求防过期机制继续保证快速切换条件时旧结果不会覆盖新结果。返回书架时沿用现有刷新机制，以便刚编辑的评分或阅读历史立即影响顺序。

## 异常与验收

- 查询失败显示现有“搜索失败，请重试”，保留重试入口；不能把读取失败当作空书架。短暂加载期间沿用现有旧结果和加载提示。
- 阅读日期为 `null`、非法日历日期或仅有弃读结束日时，不进入“最近读完”的有日期部分；同书多次读完只取最近一次。
- 在任一排序下，关键词与状态／类型／多标签筛选的结果集合不变，书卡上的摘记和图片文字命中提示不丢失。
- 自动化测试覆盖四种顺序、无日期／无评分、二刷、同日并列、筛选组合、快速切换与重试。iPhone 页面交互由用户实机验收；未实测不得标为通过。
