# Novel Tracker — 多次阅读记录设计

日期：2026-10-02

## 目标

让一本小说保留首刷、二刷及以后每次阅读的开始日期、结束日期和结果。用户仍通过现有的“阅读状态”操作，不增加“开始本次阅读”“结束本次阅读”按钮。新建或修改状态时自动维护阅读历史；日期默认当地当天，并允许在保存前修改。旧书资料、总体评分、标签与主角不得因升级丢失。

## 本次范围与边界

- 每次阅读是一条独立记录，包含稳定 ID、所属书籍、阅读序号、开始日期、可为空的结束日期及结果（在读、读完、弃读）。日期只精确到日。
- 一本书最多有一条在读记录；已结束的记录一直保留，详情页默认展开全部阅读历史。
- “想读、在读、读完、弃读”仍是书籍的当前状态。总体评分仍属于整本书，不拆成每次阅读各一个评分；改回“在读”不会清除旧评分。
- 本次提供阅读记录的日期修改和误记录删除；不加入每次阅读感想、摘记关联、阅读时长、连载完结状态、备份或统计。它们在后续独立阶段处理。

## 状态与记录的对应规则

| 操作 | 自动产生的阅读历史 |
| --- | --- |
| 新建“想读” | 不产生记录。 |
| 新建“在读” | 创建首刷在读记录；开始日期默认今天、可编辑，结束日期为空。 |
| 新建“读完” | 创建首刷读完记录；开始、结束日期都默认今天，保存前均可编辑。 |
| 新建“弃读” | 创建首刷弃读记录；开始、结束日期都默认今天，保存前均可编辑。 |
| 从非“在读”改为“在读” | 创建下一次在读记录；开始日期默认今天、可编辑。此前记录不变。 |
| 从“在读”改为“读完”或“弃读” | 将本次在读记录结束为对应结果；结束日期默认今天、可编辑。 |
| 没有在读记录而改为“读完”或“弃读” | 创建下一次对应结果的记录；开始、结束日期默认今天、可编辑。升级前已有“在读”但无记录的旧书也按此处理，不猜测真实开始日期。 |
| 状态保持不变，仅修改其他资料 | 不新增阅读记录。 |

“今天”按 iPhone 本地日历日期计算，不从 UTC 时间戳截取日期。开始日期不得晚于结束日期；无效日期、倒序日期须阻止保存并保留表单内容。状态变化和阅读记录增改必须在同一数据库事务内完成，失败时两者都不改变，重复点击不能生成重复记录。

从“在读”改回“想读”视为取消这次尚未结束的阅读尝试。若确有在读记录，保存前须明确提示会移除它；已结束的历史记录不受影响。用户取消提示时保留原状态和填写内容。升级前的旧“在读”书若还没有记录，可直接改回“想读”。从已有结果（“读完”或“弃读”）改成另一结果且没有在读记录时，依上表建立新一次记录，而非悄悄改写旧历史；界面需让用户看见即将生成的日期和序号。

## 旧数据与阅读序号

- 数据库升级不得为现有书自动伪造带日期的历史记录。旧书当前为“读完”时，只保存“此前至少读完一次”的历史标记；详情页显示“首刷：日期未记录”。此后改为“在读”会创建二刷，不要求先补填首刷日期。
- 旧书为其他状态时不凭状态推断完成过几次；下一次自动记录从首刷开始。若旧“在读”书改为“读完”或“弃读”，依前述规则生成首刷，日期可当场修正。
- 用户可以在详情页为旧书补填首刷记录，开始与结束日期默认今天、可编辑。补记只替换“日期未记录”的占位，不改变现有二刷及以后记录的序号。
- 新记录的序号高于既有序号及旧书历史标记；修改日期不改变序号。删除误记录后后续记录仍保留其序号，避免无意重命名已经形成的阅读历史；下一次创建时使用当前最大序号加一。

## 页面流程

1. 新建表单选“在读”“读完”或“弃读”时，在状态下方显示本次阅读日期。选“读完”或“弃读”时同时显示开始与结束日期；默认当天，保存前可分别修改。选“想读”则不显示阅读日期。
2. 编辑表单在状态选择发生变化时，明确展示即将创建或结束的那次记录及可编辑日期。没有变化则不额外新增记录。若是从“在读”改回“想读”，显示取消当前尝试的确认。
3. 详情页在总体评分之后显示“阅读历史”：按阅读序号依次展示结果和日期；未结束的记录显示“在读中”；旧已读书的占位显示“日期未记录”。阅读历史不出现在书架卡片上。
4. 每条已保存的记录可修改日期；删除须二次确认。删除非最新记录不改变书籍状态。若删除的最新记录正对应书籍当前状态，则状态回退为上一条已结束记录的结果；只有旧“已读”占位时回到“读完”，完全没有既往记录时回到“想读”。删除历史记录不得删书、评分或其他记录。
5. 保存失败或读取失败时显示错误、保留输入并可重试；删除失败不得从界面假装记录已消失。

## 存储、迁移与验证

- 在现有 SQLite 架构上新增阅读记录表及旧已读书的历史标记，保留既有书籍 ID 和全部字段；迁移可重复执行且不会重复生成历史。
- 新建书籍与其首条阅读记录、编辑书籍与状态导致的阅读记录变化、删除记录与必要的状态调整，分别作为单次原子操作保存。
- 自动化测试覆盖旧库迁移、各状态转换、默认日期与日期校验、二刷序号、取消在读、误删后的状态、失败回滚及重复提交。先跑相关测试，收尾再跑一次完整测试、TypeScript 与 lint；不为这项普通功能重复运行 Expo Doctor 和 iOS 导出，除非新增原生依赖或遇到打包异常。
- 请用户在 iPhone Expo Go 验收：新建“读完”并修改两个日期；把它改为“在读”产生二刷、再改为“弃读”；检查评分保留；检查旧已读书显示日期未记录且可直接二刷。真机未验证前不宣称通过。
