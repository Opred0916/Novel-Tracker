# Novel Tracker — 删除小说设计

日期：2026-10-02

## 目标

让用户可以从书架中删除误录、重复或不再需要的小说，同时清除它在当前书库里的阅读历史、摘记和图片，不留下可见的残余记录。删除是明确确认后的操作；失败时不能让界面误以为已经删除。

本功能面向目前的离线个人书库。用户已经确认下一步开发“删除小说”；原有总需求也规定在小说详情页底部提供删除入口，并在删除前确认。

## 本次范围

- 在小说详情页底部提供“删除小说”，与“编辑资料”保持明显区分。
- 删除前展示书名和影响范围，要求用户再次确认。取消时不修改任何数据或文件。
- 确认后删除当前书库里的这本小说及其主角关联、标签关联、阅读历史、摘记、摘记图片关联、精彩片段关联、封面关联和该书拥有的图片资产。
- 标签库中的系统标签和用户自定义标签，以及快捷标签设置，属于全局资料；即使某个标签只被这本书使用，也不随书删除。
- 删除成功后返回书架，搜索和筛选结果立即更新；其他书及其图片不受影响。
- 已导出的 `.noveltracker` 备份文件不会被修改。旧备份可能包含已删除的书；从旧备份恢复仍按现有“完整替换当前书库”的规则进行。

不做批量删除、回收站、应用内撤销或自动为待删除书生成备份。删除一本书也不删除全局标签或手机相册里的原图。

## 页面与交互

- 删除按钮放在详情页主要操作之后，使用危险操作样式，不放在书架卡片的轻触区域，避免误触。
- 点击后弹出确认框，文案说明：将删除《书名》以及它的阅读记录、摘记、精彩片段和封面；删除后无法在应用内撤销。提供“取消”和“删除小说”两个明确选项。
- 确认后按钮进入处理中状态，禁止重复提交；删除期间不再允许继续编辑这本书。
- 数据库删除成功后返回书架。书架重新读取本地数据，已删除的书不能仍留在列表或搜索结果里；详情页也不能继续显示旧缓存。
- 如果用户从旧链接进入已删除书的详情页，显示现有的“找不到这本小说”和“返回书架”入口。
- 如果数据库删除失败，留在详情页并显示可理解的错误，原书及关联记录保持可用，可重试。
- 如果数据库已成功删除、但某个本地图片文件暂时无法清理，书仍视为删除成功；应用在后续启动时重试文件清理，不向用户谎称数据库删除失败，也不恢复已删除书。

## 数据与图片清理

目前数据库为版本 7。`book_protagonists`、`book_tags`、`reading_sessions`、`notes`、`note_images`、`highlight_images` 和 `image_assets` 已通过外键与书籍及彼此关联。一本书的封面也作为该书拥有的 `image_assets` 保存。删除操作应由书籍仓储统一提供，页面不直接运行 SQL 或删除图片。本次增量迁移到版本 8，新增仅供应用内部使用的 `pending_image_deletions` 表，以待删图片路径为主键；该表不进入备份。

1. 在一次 SQLite 独占事务中确认书籍存在，收集该书拥有的全部 `image_assets.local_path`，并检查这些图片 ID 没有被其他书错误引用、这些路径也没有被其他书的图片资产共用。若检测到跨书引用或共用路径，拒绝删除并提示数据关联异常，避免连带损坏其他书。
2. 在同一事务中清空待删除书的 `cover_image_id`，再删除该书记录。依靠已启用的 SQLite 外键级联清除子记录；保留 `tags` 和 `quick_tags`。事务提交失败则全部回滚。
3. 为每个待清理图片路径在事务中写入 `pending_image_deletions`。这样即使 App 在数据库提交后、删除文件前退出，后续仍能继续处理。
4. 事务提交后，逐个删除应用私有目录中的对应图片文件。图片在同一本书的封面、摘记和精彩片段中复用时只删除一次；文件已不存在视为清理成功。
5. 删除文件前再次确认路径仍不被当前 `image_assets` 引用，且位于应用管理的图片目录内。文件系统失败时保留该清理任务，在下次启动重试；不会因清理失败去回滚已提交的书籍删除。

数据库升级只增表，不重建或清空现有书库。现有备份格式不变；恢复备份时保留待清理任务，但每次执行前仍检查路径是否被新书库引用，不能误删恢复后的图片。

图片可能来自相册、封面链接或旧备份恢复，因此不能只删除 `novel-tracker/<bookId>/` 整个目录：备份恢复的图片可能与其他书位于同一恢复分代目录。清理按数据库收集到的具体图片文件路径进行，不触碰手机相册、用户保存的备份包或其他书的文件。

## 与现有功能的关系

- 删除后书架列表、书名／作者／主角／摘记搜索、状态／类型／标签筛选都不再返回这本书。
- 备份概览和新导出的备份不再包含这本书及它的图片；删除前已经导出的备份保持原样。
- 恢复旧备份可能让这本书重新出现，而且恢复是完整替换，可能覆盖删除之后新增的记录；确认删除文案不把备份描述成一键撤销。
- 未被其他书使用的自定义标签仍留在标签库，用户可在现有标签管理功能中处理，不由删除小说顺带清理。
- 删除书籍不会重新编号其他书的阅读次数，也不会修改其他书的摘记或评分。

## 错误与边界情况

- 重复点击删除、已被删除的书、数据库写入失败或外键关联异常，都应给出确定结果，不能出现按钮显示成功但书仍存在。
- 文件缺失、文件被占用或暂时无法删除时，不影响已经提交的数据库删除；待清理任务会保留以供重试。
- 清理器只处理应用拥有且当前数据库不再引用的图片路径。遇到越界路径或仍被引用的路径时不删除，并保留或报告异常，避免误删。
- 若备份导出正在读取图片而同时删除书籍，现有备份完整性校验必须保证不会生成看似成功的残缺备份；不要求在本次新增全局编辑锁。

## 验收标准

1. 删除无图片、无摘记的普通书后，它从书架、搜索和筛选中消失；取消确认则完全不变。
2. 删除有封面、二刷记录、多条摘记及多张精彩片段图片的书后，数据库中对应的子记录和该书图片资产均消失；同一图片被多个摘记复用时只清理一次。
3. 删除一本书不影响另一书，也不删除系统标签、自定义标签或快捷标签配置。
4. 模拟数据库事务失败时，书和关联记录仍可打开，图片文件不被提前清理。
5. 模拟图片清理失败及 App 中途退出时，书已从当前书库删除；后续启动能安全重试，不误删仍被引用的文件。
6. 删除后生成的新备份不含该书；删除前的备份仍能按现有完整替换流程恢复。
7. 在 iPhone Expo Go 上实际完成一次取消删除、一次确认删除，并检查书架刷新、其他书不受影响及重新打开 App 后结果仍保持。

## 后续可能扩展

若将来确有误删恢复需求，再单独设计回收站或限时撤销；这需要定义保留期限、图片占用和备份规则，不与本次可靠删除混在一起。
