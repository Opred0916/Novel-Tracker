# Novel Tracker — 小说封面设计

日期：2026-10-02

## 目标

让用户给每本小说设置一张封面，在书架和小说详情中更容易辨认书籍。封面始终可选；没有封面的旧书和新书继续正常显示。用户可以从 iPhone 相册选择图片，或输入一张网络图片的链接。成功选取后，应用保存自己的本地副本，离线时仍能显示，并随完整备份一起迁移。

本功能面向目前的离线个人书库，不依赖书目数据库、账号或图片搜索服务。用户之前提出“可以选择联网的图片”；本轮确认的具体方式是**输入图片链接**，不在应用内搜索图片。

## 本次范围

- 每本书最多设置一张封面；可以在新增小说时选择，也可以在编辑资料时新增、更换或移除。
- 来源有两种：从相册选一张图片；输入一条直达图片文件的 HTTPS 链接并下载。
- 书架卡片与小说详情页显示同一张封面。无封面、文件缺失或加载失败时显示统一的默认封面，不出现破图或空白占位。
- 更换封面不会修改书名、阅读状态、评分、阅读历史、摘记或精彩片段。
- 原有备份可继续恢复；新生成的备份包含封面图片和它所属的书籍。

不做自动搜索封面、根据书名抓图、网页截图、在线热链接显示、封面裁剪编辑、封面图库或多封面历史。网络图片由用户自己提供链接；界面不暗示图片已获公开传播许可。

## 页面与交互

### 新增和编辑小说

- 在书名附近显示“封面（可选）”区域。默认封面下提供“从相册选择”和“输入图片链接”两个入口。
- 选择相册图片后先显示预览；取消选择则保持当前状态。输入链接后点击“获取图片”，下载并验证成功才显示预览。输入框可修改并重试。
- 保存小说时才正式关联封面。只填书名仍可直接保存“想读”小说，不要求选封面或等待网络。
- 编辑已有小说时可更换或移除封面；操作先在表单内预览，点击“保存”后才生效。离开表单而未保存时，原封面不变。
- 正在获取网络图片时，区域内显示进度状态并防止重复点击；不锁住书籍其他字段。下载失败时保留用户输入的链接与原封面，并显示可重试的错误提示。
- “移除封面”只移除书籍的封面关联，不影响该书的精彩片段和摘记图片。

### 书架和详情

- 书架卡片左侧使用固定比例的封面缩略图，文字仍以书名为主；长书名与搜索命中的摘记摘要不能被封面挤出可读区域。
- 小说详情的基本资料区显示较大的同一张封面；点击编辑资料可更换或移除。
- 未设置封面时使用应用内置的默认封面样式，不自动向网络请求图片。图片加载失败时同样回退到默认样式，并允许用户进入编辑页处理。
- 书架仍按既有的最近修改时间排序；封面的增加、更换或移除属于资料修改，更新该书的 `updatedAt`。

## 图片获取和安全边界

- 相册沿用项目已安装的 `expo-image-picker`，只选一张图片；不要求访问整个相册的持续权限。保存前将图片复制进应用管理的文件目录，不长期依赖选择器的临时 URI。
- 网络来源只接受 `https://` 直达图片的链接。拒绝 `http://`、`file://`、`data:`、空链接和非图片响应；跳转后的最终地址也必须是 HTTPS。
- 下载前检查服务器声明的类型和大小；下载中按实际收到的字节再次限制大小。第一版单张封面最多 10 MiB，超限立即停止并清理临时文件；不能只相信 `Content-Length`。
- 支持可正常解码的 JPEG、PNG、WebP，以及 iPhone 相册选择器返回且设备能够显示的图片格式。文件扩展名和响应头不能单独证明它是图片；保存前验证实际内容可作为图片显示。无法识别的格式给出“这张图片无法使用”的提示。
- 图片保存在应用私有目录，文件名由应用生成，不拼接用户输入的 URL、书名或远端文件名；也不把来源链接用作长期图片地址。
- 网络超时、离线、无效证书、404、不是图片、图片过大或存储不足时，旧封面和现有书籍资料保持不变。清理本次下载和预览产生的临时文件。
- 图片链接可能涉及第三方网站及隐私；只有用户主动点击“获取图片”时才请求该地址。应用不在打开书架时重新访问来源网站。

## 数据与事务

当前数据库版本为 6。下一次迁移给 `books` 增加可空的 `cover_image_id`，引用现有 `image_assets.id`；旧记录迁移后为 `NULL`。`image_assets` 继续保存图片稳定 ID、所属书籍、本地路径和创建时间，不新增远程 URL 字段。保存封面时检查图片确实属于这本书。

```text
books.cover_image_id TEXT NULL → image_assets.id
image_assets: 封面、摘记图片、精彩片段图片共用现有图片资产表
```

- 封面引用与书籍资料在一次数据库事务中写入。复制或下载失败时不修改数据库；数据库提交失败时清理本次创建的图片文件。
- 更换和移除后，只在旧图片不再被封面、摘记或精彩片段引用时删除对应资产和文件。删除整本书时一并清理它拥有且不再被引用的图片。
- 不允许把甲书的图片 ID 设置为乙书封面；恢复备份时也执行同样的归属检查。
- 避免将图片二进制存入 SQLite，数据库只保存关联与本地路径。列表查询应一次获得封面路径，避免每张卡片再发独立查询。

## 备份格式兼容

当前备份格式为 `formatVersion: 1`。封面是新增的书籍与图片关联，因此新导出的备份使用 `formatVersion: 2`：每条书籍记录增加可空的 `coverImageId`。现有 `images` 清单继续保存所有被引用图片，包括封面；同一图片若还被摘记或精彩片段引用，只存一份二进制文件。

- 恢复第 1 版备份时，视每本书的 `coverImageId` 为 `null`，按原有规则恢复其余资料和图片。
- 恢复第 2 版备份时，校验 `coverImageId` 存在于图片清单、属于同一本书、图片字节完整且内容可读，再允许进入恢复预览。
- 第 2 版备份的完整替换、二次确认、空间限制和失败回滚沿用已有设计。验证失败不得改变当前书库。
- 应用若遇到高于自身支持的备份格式版本，继续明确拒绝，不尝试部分恢复。
- 升级或恢复后，无封面书籍仍显示默认封面；不能为了补封面而删除原有摘记或精彩片段。

## 验收标准

1. 旧书与只填书名的新书都能正常显示默认封面；离线打开书架不发起封面网络请求。
2. 从相册设置封面后，书架和详情一致；关闭并重新打开应用仍显示，编辑更换和移除也正确保存。
3. 输入有效 HTTPS 图片链接后，保存到本地；断网重开仍显示。无效链接、非图片和超限图片均给出错误，原封面不变。
4. 编辑表单中选择或下载封面后直接返回，已保存的书籍和原封面不变，临时文件最终得到清理。
5. 给有封面的书导出并恢复新备份后，封面及所有原有书籍、阅读记录、摘记与精彩片段均完整；第 1 版备份仍可恢复，书籍显示默认封面。
6. 缺失封面文件、错误的图片归属或损坏的第 2 版备份在恢复前被拒绝，当前书库保持不变。
7. 在 iPhone Expo Go 上完成相册选图、网络下载、离线显示、替换／移除和备份恢复的实际操作。

## 后续可能扩展

应用内搜索网络封面、自动匹配书名、裁剪和图片来源管理留待后续独立设计。未来若加入 AI 或联网书库，仍须先展示候选封面供用户确认，不能覆盖用户手动选择的封面。

## 技术依据

- [Expo SDK 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/) 已包含在 Expo Go，项目目前已用于摘记和精彩片段选图。
- [Expo SDK 57 FileSystem](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/) 提供应用私有文件的读写与复制能力；具体网络流式下载 API 在实施计划阶段按 SDK 57 文档再次核对。
