# Novel Tracker — 首次使用与数据安全引导设计

日期：2026-10-09

## 目标与定位

让首次使用者知道书库保存在当前应用的本地空间，并在开始积累记录后知道如何制作、保存和恢复完整备份。为将来从 Expo Go 迁移到独立版提供可反复查看的操作说明，避免误以为安装新版本会自动带走旧记录。

这是现有手动备份能力的引导层，不增加云同步、自动备份或新的恢复方式。用户应能立即添加小说；引导不能成为首次使用的必经步骤，也不能让书架长期多出工具按钮。

## 本轮范围

- 空书架首次进入时显示一次简短、可关闭的数据说明，并提供“了解备份”入口。
- 书库已有小说且尚未生成过备份时，在“管理”页显示一次可关闭的备份提醒。
- 在“管理”页增加长期可访问的“使用与数据安全”页面，说明本地存储、手动备份和 Expo Go 到独立版的迁移步骤。
- 复用现有“备份与恢复”页面及 `.noveltracker` 文件；不改变备份格式、恢复事务或书库数据结构。

本轮不包含自动或定时备份、系统通知、账号、云同步、跨设备自动迁移、备份文件是否确实存入外部位置的自动检测，以及 App Store/TestFlight 发布流程。

## 入口与页面表现

### 首次使用说明

仅当书库为空、当前位于“全部”分区且该设备尚未关闭过说明时，在现有空书架提示下显示一张小卡片：

> 书库记录保存在这台设备的应用中。开始记录后，记得将完整备份保存到“文件”或你信任的位置。

卡片提供“明白了”和“了解备份”。点击任一操作均记住已看过，不再自动出现；“了解备份”进入“使用与数据安全”。无论用户是否处理卡片，“添加小说”始终可见、可用。筛选或搜索造成的空结果不显示这张卡片。已有书库的老用户不会突然在书架上看到首次使用卡片。

### 一次性备份提醒

当书库至少有一本小说、现有备份服务报告“尚未生成备份”，并且该设备尚未处理过提醒时，在“管理”页顶部显示一张简洁提醒卡。文字为“书库已有记录，建议生成完整备份，并在系统分享界面把文件保存到‘文件’等位置。”操作为“去备份”和“暂不提醒”。点击任一操作都记住已处理，后续不自动重复；“去备份”打开现有“备份与恢复”页。

提醒只在“管理”页出现，不遮挡书架和添加流程，不使用弹窗或系统通知。生成过备份的老用户不补发提醒。读取书库或备份概览失败时暂不显示提醒，也不把失败当作“已备份”；常驻的帮助入口和备份入口仍可用。

### 常驻指引

在“管理”页的“导入与导出”区域加入“使用与数据安全”，打开独立可滚动页面。页面分为“记录存在哪里”“怎样保存备份”“从 Expo Go 迁移到独立版”三个短节，并提供通往现有“备份与恢复”的按钮。它是帮助页面，不承载文件生成或恢复逻辑。

迁移步骤明确为：

1. 在仍可打开旧书库的 Expo Go 中进入“备份与恢复”，生成完整备份。
2. 在系统分享界面将 `.noveltracker` 文件保存到 iPhone“文件”或可信的外部位置，并确认能找到该文件；不要只停留在分享界面。
3. 安装独立版后，在独立版的“备份与恢复”中选择该文件，查看预览并确认恢复。
4. 核对小说、阅读记录、摘记和图片无误后，再清理旧环境。

页面说明 Expo Go 与独立版的数据空间不会自动互通；恢复会完整替换独立版当前书库，因此若独立版已有新记录，应先备份该书库再恢复旧文件。备份包含私人摘记与截图，提醒用户不要随意公开分享。

## 状态与数据边界

- 首次使用说明和一次性提醒各有独立的本机布尔标记，沿用项目已有的本机键值存储能力；不新增 SQLite 迁移，不纳入书库备份。换设备或重新安装后重新出现是合理行为。
- 标记仅在用户明确点击“明白了”“了解备份”“去备份”或“暂不提醒”后写入；只是看到页面、切换标签或程序中断不算处理过。
- 书籍数量与“上次生成备份”来自现有 `BackupService.getOverview()`，不重新维护一套计数。
- `lastGeneratedAt` 只表示应用成功生成过备份文件，不表示用户已在系统分享目标保存文件；所有文案保持这一区别，不使用“已安全备份”等结论。
- 提醒与指引不修改小说、阅读记录、摘记或图片。现有备份生成、分享、验证和完整替换恢复流程保持原样。

## 失败与可用性

- 本机引导标记读取失败时，不阻塞应用；本次不自动弹出或重复提示，常驻指引仍可访问。
- 用户点击关闭类操作后若标记保存失败，当前页面仍可继续使用；下次可能再次出现提示，但不能影响书库数据。
- 页面和提醒使用当前主题色、iPhone 安全区与现有字号层级；小屏和大字号下可滚动，按钮有清晰文字与无障碍标签。
- 帮助页面的“去备份”只负责导航；若备份服务出错，由现有备份页展示原有错误，不在引导层伪报成功。

## 架构

1. 新增轻量的本机引导偏好模块，分别读写 `introSeen` 与 `backupReminderHandled`，集中处理存储异常，不与书库表混合。
2. 书架空状态仅负责展示一次性说明并导航，不在书架页面实现备份逻辑。
3. “管理”页读取现有备份概览决定是否显示提醒，用户处理后持久化标记；其余管理入口保持不变。
4. 新增“使用与数据安全”静态帮助路由，链接现有备份页；备份服务接口和文件格式保持不变。

## 测试与验收

- 全新空书库首次进入“全部”可见说明；关闭后即使重启也不再出现；添加按钮始终可用。
- 搜索或筛选导致的空结果、已有小说的书架不显示首次说明。
- 有小说且从未生成备份时，“管理”页显示一次提醒；“去备份”和“暂不提醒”都会令其后续不重复。
- 已生成备份时不补发提醒；概览读取失败时不误称已备份，也不阻断管理入口。
- 帮助页面始终能从“管理”打开，迁移步骤明确保存外部文件、恢复完整替换和恢复后核对。
- 文案不把 `lastGeneratedAt` 当成外部文件已保存的证明；取消分享不会出现“已安全备份”的提示。
- 不改现有备份格式和恢复数据；现有备份与恢复测试继续通过。
- iPhone 真机确认卡片、提醒、帮助页在安全区和大字号下可阅读、可点击，且不会遮住“添加小说”。
