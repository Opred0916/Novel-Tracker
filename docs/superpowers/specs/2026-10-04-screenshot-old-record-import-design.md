# Novel Tracker — 旧记录截图导入设计

日期：2026-10-04

## 目标与本轮边界

让用户从相册选择多张旧记录截图，把其中的小说书目和当时写下的想法整理进现有书库。用户提供的微博截图包含“编号＋书名”的主评论、后续回复、显示时间和“共 N 条回复”等界面文字；这些内容是本轮的主要验收样例。成功的导入应减少逐字重输，同时让用户能对照原图检查每一本书、每一条想法的文字及归属。

本轮只处理用户主动选择的本地图片。图片文字在支持 Apple Vision 的 iPhone 专用开发版中离线识别；识别出的内容始终是**待确认候选**，不直接写入书库。Expo Go 没有项目自定义的原生识字模块，但仍可选图并手动输入或修正文字，完成同一套预览和导入。既有文字／TXT／CSV／XLSX 导入保持原入口和行为。

不抓取微博链接、登录微博、展开未显示的回复，不把截图上传给大模型或第三方 OCR，也不在本轮根据图片推断题材标签、生成简介或联网补充书籍资料。以后若增加大模型候选识别，仍须进入同一人工确认流程，并单独设计隐私、费用和来源标记。

## 方案选择

比较三种做法：直接把 OCR 结果保存为书会把识字错误永久写入书库；先调用联网模型可推测更多字段，但需要上传私人截图并引入账号、费用和网络依赖；本轮采用**本地识字 → 对照原图修正文字 → 保守生成候选 → 现有导入预览 → 最终确认提交**。它复用已有的本地 OCR 和导入提交能力，也保留用户处理识别错误的机会。

截图导入是新的输入适配器，不把多张图片的 OCR 原文简单拼成一篇 TXT。每张图片保留自己的顺序、识别状态、可编辑文字及来源编号。只有用户明确标记“接上一张”时，解析才可跨图片延续同一条书目或回复；默认各张独立，避免上一张末尾的回复误归入下一张的书。

## 选图、顺序与识字

- 在“数据管理 → 追加旧记录”增加“从截图导入”。一次可从相册选择多张图片，本轮单批上限为 20 张；超过上限时提示分批处理，不截断已选内容。仅接受图片，不能把视频或网页链接当作截图。
- 选中后显示缩略图和“第 1 张／第 2 张……”顺序。iPhone 选择器启用带序号的多选；进入应用后仍可调整顺序、移除误选图片，并为后续图片标记是否“接上一张”。调整顺序或连续关系后须重新生成候选，不能保留已过期的归属建议。
- 逐张识别，页面显示当前进度和每张结果；不在 JS 内一次加载所有图片的 Base64。识字使用所选图片的本地临时 URI，不先把截图作为书籍封面或精彩片段保存。
- 每张图都可展开原图，与可编辑的多行识别文字并排／上下核对。OCR 无文字、失败或某张图片损坏时，不丢弃其他图片；该张显示原因、可重试入口及手动录入框。用户可编辑、增删行，纠正序号、书名、回复和日期后再解析。
- 没有原生 OCR 模块时明确显示“当前使用 Expo Go，图片文字需手动输入；自动识别需要专用开发版”。手动文字走同一解析和预览流程，不假装识别已经成功。相册选择取消不清空当前未提交草稿。

## 从截图文字到候选

- 用户在生成候选前选用已有的“每行一本书”“字段段落”或“编号＋回复”格式，并选择整批默认阅读状态；默认仍为“想读”。编号模式适用于用户提供的微博样例，但不能承诺识别任意微博页面布局。
- 每张图先独立保留其文字行与来源。解析器可复用已有确定性规则，但需要截图适配层保留“第几张、原文第几行”的来源定位，供预览回看；这种来源引用属于本次导入草稿，不新增永久书籍字段。
- 明确的 `144残次品` 可建议为编号 144、书名“残次品”；编号只是旧清单序号，不成为评分、阅读次数或新书 ID。`top1`、`top3`、“好痛”、emoji 等只可能是想法文字，不作为评分或标签。用户名、“博主”、点赞数和“来自江苏”等界面信息不成为作者或阅读平台。
- OCR 不能可靠恢复视觉缩进和微博回复层级。回复与某本书的关联只有在经过用户核对后才成为可导入摘记；归属不清的文字进入待处理片段，不自动附给截图里最近的书。预览必须允许把片段指定给某个候选书、创建新候选、修改为想法或明确忽略；“标记已处理”需说明选择的去向，不能悄悄丢失文字。
- `共 N 条回复` 仅提示可能还有未展示的回复。若截图只显示前几条，预览说明“截图未包含全部回复”；应用不会声称已导入 N 条。跨截图连续关系由用户显式确认，不能仅凭相邻图片自动合并或把同名书静默去重。
- 单张截图可以形成多本候选书；多张图也可能属于同一本书。预览中可拆分、合并本批候选并移动想法；合并只影响本次草稿。没有识别出书名时仍可手工建候选，不能把整页 UI 文本当成书名。

## 时间与资料真实性

- 微博主评论和回复旁的显示时间代表**发布记录的时间**，不等于开始或读完小说的日期。相册图片的拍摄／保存时间也不能作为阅读日期。
- 有完整四位年份、月、日的回复时间，可作为该条想法的“原记录时间”候选，用户核对归属后确认；两位年份（如 `24-10-27`）必须在预览中补成并确认四位年份才可保存为日期。时间读不清、缺失或与回复归属不明时保持“记录时间未注明”。时间不能凭导入当天、图片元数据或相邻评论推测。
- 截图没有明确写出阅读状态或阅读日期时，沿用用户选的整批默认状态，日期保持未知。用户可在预览中逐条改状态、补阅读日期和评分；`top1`、旧清单编号、点赞数不作为评分或读完证据。
- 作者、主角、平台、类型和标签仅在截图文字有明确字段标记或用户亲自填写时形成候选。不根据书名或评论内容猜资料。导入后的“我的想法”必须是用户确认保留的非空文字；OCR 原文和搜索索引不能冒充用户想法。

## 预览与提交

1. 选图并检查顺序；逐张完成 OCR 或手工文字。用户可以在图片与文字之间反复核对，选择解析格式和默认状态后生成候选。
2. 候选预览列出书名、来源图片及行号、拟导入的想法、原记录时间、阅读状态和日期；每项可编辑、跳过、新增为独立书目，或向现有书仅追加已确认想法。图片文字识别不确定的字段应有明显提示。
3. 沿用现有书名和想法重复提醒。重复截图、相同书名或相似 OCR 文字不触发自动合并；再导入同一组截图时仍逐项提示，由用户决定。提交前重新检查目标书和重复项。
4. 待处理原文必须逐段明确指定去向或忽略。最终确认显示新增书数、追加想法数、跳过项数、忽略片段数及仍有来源未处理的提示；未处理项不能越过确认页直接保存。
5. 只有最终确认才调用现有导入提交服务，以一个事务追加记录；提交失败保留已修正的文字与预览，当前书库不变。取消或退出不写入书库，也不删除用户相册中的原图。

截图原图只用于本次校对，默认不作为书籍封面、精彩片段或摘记图片入库，也不进入备份与开放导出。草稿仅在当前导入会话中保留；应用被系统关闭后不保证恢复。临时图片副本在退出或完成后尽力清理，不能触碰相册原图。

## 模块边界与兼容

- 选图适配器返回有序的本地图片引用；现有 `LocalImageTextRecognizer` 负责单张图片的本地文字识别。识别调用可在无模块时安全返回“不可用”，不改变已有书籍图片 OCR 的队列和搜索索引。
- 新的截图导入草稿保存图片顺序、连接关系、OCR 状态、用户修正文字及来源定位；截图解析适配器将它转换为现有 `ImportCandidate`／`ImportFragment`。普通文字导入不需要经过选图或 OCR。
- 现有 `ImportReview` 负责逐项修改、片段归属和重复处理；当前界面只有“标记已处理”，尚不能把片段指定给某书或新建候选，本轮须补齐该交互，不能仅凭旧设计文档宣称已经支持。
- `ImportCommitService` 只接收已确认的候选，不接收图片 URI 或 OCR 原文；本轮不新增数据库表，不变更备份格式和开放导出格式。确认写入的书、阅读历史和想法照常进入现有备份／导出。
- 本轮优先 iPhone；Android 暂无项目本地 OCR 实现，可选图后手工录入。Expo Go 可以验收选图、手工校对和导入事务，但自动识字须在装有原生模块的 iPhone 专用开发版真机验收。Windows 上的模拟测试和 TypeScript 检查不能代替 Swift 编译或中文截图识别实测。

## 失败、性能与隐私

- 一批最多 20 张，逐张处理并显示进度；用户可取消尚未开始的识别。某张失败不影响其他张和已修改的文字；重新识别前告知会替换该张自动结果，用户修改过的文字不得被静默覆盖。
- 识字结果为空、图片无法读取、相册授权被拒绝、选图取消、原生模块缺失或解析后无候选，都给出明确提示及手工处理路径。大量文字仍受现有 1 MiB 文本和 500 个候选上限约束；超限提示分批导入，不截断或部分提交。
- 截图及识别文字仅在设备本地处理，不上传、不记录全文日志。用户曾选择但未确认导入的图片和文字不进入 SQLite。导入后只有最终确认的书目、阅读记录与想法成为持久数据。

## 验收标准

1. 一次选多张截图，顺序可见且可调整；独立／接上一张的选择决定跨图关联，重新排序后旧候选不会被误用。用户取消选图或移除某张，不影响当前书库和相册原图。
2. 在支持本地 OCR 的 iPhone 专用开发版中，用用户微博样例的匿名化截图离线识别“编号＋书名”、可见回复和时间；原图与文字可逐张对照并编辑。失败一张仍可处理其余图片，且可手工补录。
3. OCR 把“编号、用户名、博主、地区、点赞、共 N 条回复”混在一起时，只有核对后的书名和想法进入候选；隐藏回复不会凭数量补造。不同书和跨截图回复不被自动错配。
4. 两位数年份需要用户明确确认四位年份；微博发布时间不变成阅读日期。未知阅读日期和未知想法时间在保存、详情、年度回顾及备份后仍保持未知。
5. 可在预览中修正书名、移动或忽略片段、处理重复并最终确认；取消、OCR 失败或提交失败不会写入半批数据。成功后新增和追加内容可在书架搜索、详情、备份及开放导出中找到。
6. Expo Go 中选图和手工输入路径可完成相同导入，页面明确说明自动识字不可用；已有文字／表格导入、精彩片段 OCR 搜索以及普通书籍操作保持正常。

## 技术依据

- [Expo SDK 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/)：支持图片多选、iOS `orderedSelection` 和选择数量限制；图片选择可在 Expo Go 使用。
- [Expo development builds FAQ](https://docs.expo.dev/develop/development-builds/faq/)：项目自定义原生 OCR 模块需要专用开发版，不能直接装进 Expo Go。
- [旧记录文字导入设计](2026-10-03-old-record-text-import-design.md)与[本地图片文字识别与搜索设计](2026-10-04-local-image-ocr-search-design.md)：本轮分别复用候选预览／原子提交和本地识字接口，不更改既有数据含义。
