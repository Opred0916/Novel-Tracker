# Novel Tracker — 开放格式完整导出设计

日期：2026-10-03

## 目标

让用户不依赖 Novel Tracker，也能取回并阅读自己的完整书库：小说资料、分类标签、阅读历史、摘记、封面与精彩片段图片。用户主动导出一个标准 ZIP 文件，可在电脑上解压，用文本编辑器查看 JSON、用表格软件查看 CSV、用图片查看器打开原图。

这是当前本地版“数据归用户”的功能。现有 `.noveltracker` 备份仍负责在 App 内完整恢复；本功能提供通用格式的**只读副本**，第一阶段不承诺把这个 ZIP 导回 App，也不将它误标为可恢复备份。

## 方案选择与本次范围

单独导出 CSV 便于阅读，却无法无损表达一张图片被多条摘记引用等关系；只导出 JSON 能保留关系，对普通用户又不够直观。采用一个 ZIP 同时包含：

- `library.json`：完整、可机器读取的数据和关联，是结构化导出的权威版本。
- 若干 UTF-8 CSV：面向人的常用视图，展示书目、阅读历史和摘记；按记录 ID 与 JSON 和图片索引对应。
- `images/`：数据库引用的封面和精彩片段原图，每个图片资产只放一份。
- `README.txt`：中文说明、文件目录、字段含义、日期未知的表示方式、隐私提醒，以及 CSV 与 JSON 的区别。

导出当前**全部**书库，包括空书库。第一阶段不做按书筛选、在线上传、自动定时导出或第三方同步。

## 文件结构与格式

用户看到的文件名为 `NovelTracker-export-YYYYMMDD-HHMMSS.zip`；时间取导出设备本地时间，避免同日多次导出覆盖。ZIP 内部使用固定英文文件名和 UTF-8 编码，与界面语言无关：

```text
NovelTracker-export-YYYYMMDD-HHMMSS.zip
├── README.txt
├── library.json
├── books.csv
├── reading-history.csv
├── notes.csv
├── images.csv
└── images/
    ├── <image-id-1>.<ext>
    ├── <image-id-2>.<ext>
    └── ...
```

### `library.json`：完整结构

- 顶层包含 `exportFormat: "novel-tracker-open"`、独立于备份格式的 `formatVersion: 1`、`exportedAt`、`appVersion` 和数据数量。
- 数据集合包含 `books`、`protagonists`、`tags`、`bookTags`、`quickTags`、`readingSessions`、`notes`、`noteImages`、`highlightImages` 和 `images`。现有的稳定记录 ID、排序位置和关联 ID 原样保留。
- 小说包含书名、作者、状态、作品类型、半星评分、旧版阅读次数、封面图片 ID、创建及更新时间；阅读记录包含序号、结果、可空开始／结束日期；摘记包含正文、创建／更新时间、可空阅读记录 ID、来源类型及可空的原记录日期／时间。
- 图片记录包含图片 ID、所属书 ID、创建时间、扩展名、字节数和 ZIP 内相对路径；**不包含**手机上的绝对本地路径。封面、精彩片段和摘记图片的关系通过 ID 与各关联集合表达。
- `null` 表示未知或未填写，不能把旧记录未知日期、原摘记时间、作者或评分补成导出当天；不会把导入微博时的清单序号写成阅读次数。
- 枚举值使用稳定的内部代码，如 `want_to_read` 和 `finished`；`README.txt` 给出中文对照。JSON 以 UTF-8 无 BOM 输出，日期和时间保留原有精度，不擅自添加时区。

开放格式版本独立演进。未来新增字段时保留既有字段语义，不能用 `.noveltracker` 的备份版本号解释开放导出文件。

### CSV：易读视图

- `books.csv`：每书一行，包含 `book_id`、书名、作者、阅读状态、作品类型、总体评分（0.5～5 星）、主角名字、标签名字、封面相对路径及创建／更新时间。多主角和多标签按已有顺序展示；这些展示列只供阅读，精确列表与关系以 JSON 为准。
- `reading-history.csv`：每次阅读一行，包含 `session_id`、`book_id`、书名、阅读序号、结果、开始／结束日期；日期未知时留空。
- `notes.csv`：每条摘记一行，包含 `note_id`、`book_id`、书名、正文、关联的 `session_id`（如有）、原记录日期／时间、记录来源、创建／更新时间，以及关联图片 ID 列表。
- `images.csv`：每张图片资产一行，包含图片 ID、所属书 ID、相对路径、用途（封面／精彩片段／摘记，可多项）、关联摘记 ID。共用图片仅列一次，关系仍以 JSON 为准。
- CSV 使用固定英文列名、UTF-8 BOM、RFC 4180 风格的双引号转义和 CRLF 行结束符，以便 Windows 常见表格软件识别中文、逗号和多行摘记。对以 `= + - @` 开头（忽略开头空白与控制字符）的用户文字，CSV 展示值前加单引号，避免表格软件将其作为公式执行；`library.json` 与图片保持原文／原字节。`README.txt` 解释 CSV 可能多一个安全前缀，精确内容以 JSON 为准。
- 空书库也生成带表头的 CSV，不把系统预置标签遗漏：即使尚无小说，`library.json` 仍保留当前标签库和快捷标签设置。

## 页面流程

1. 在“数据管理”页增加“导出开放格式”入口，与“追加旧记录”和“备份与恢复”并列。页面简要说明 ZIP 可在 App 外查看，`.noveltracker` 仍用于恢复。
2. 进入导出页后展示当前书籍、阅读记录、摘记和图片数量，并提示导出文件可能含私人感想与截图。
3. 点击“生成并分享”后禁用重复点击，显示“整理记录／检查图片／打包文件／准备分享”的阶段；不在这一步修改书库。
4. 生成成功后打开 iOS 系统分享面板，可存入“文件”或其他用户选择的位置。取消分享只清理本次临时 ZIP，不声称文件已保存；页面不把“生成成功”误写为“已安全备份”。
5. 生成或分享失败时显示可理解的错误，可重试；既有书库不受影响。

## 数据与实现边界

- 复用现有备份仓储读取一致 SQLite 快照的能力及图片文件读取接口，但开放导出的序列化器、格式版本和页面文案独立于 `.noveltracker` 备份／恢复。不要把私有备份简单改扩展名冒充开放格式。
- 所有图片引用都必须对应实际可读文件，且包内图片数量、路径、大小与 `library.json` 一致。遇到缺失图片、读写失败或容量不足时整体失败，不交付缺图的“完整导出”。
- 生成期间如数据或图片发生变化，以已取得的同一份快照为准；若图片不再匹配快照则报错，用户重试。不能把导出前后两次查询的不同状态拼在一个包里。
- 以已有 Expo Go 可用的纯 TypeScript ZIP 与 Expo FileSystem 分块文件接口生成归档；图片按块处理，不把所有图片同时放入内存。使用随机操作目录保存临时文件，分享结束、取消或失败后清理。
- ZIP 条目只允许固定的文档文件和 `images/<编码后的图片 ID>.<受支持扩展名>`；禁止绝对路径、`..`、重名条目和路径分隔符注入。继承当前备份可处理的文件数量与总体大小安全上限，实施计划中用现有常量和真机能力核对具体数值。
- 对每个导出集合做关联校验：书、标签、阅读记录、摘记和图片 ID 唯一，引用对象存在，数量与实际文件一致。生成失败不留下对外可分享的半成品。
- 导出不会对书库写 SQL，不改变上次备份时间，也不清理用户已保存的导出文件。

## 错误与隐私

- 区分“图片不存在或无法读取”“手机空间不足”“数据关联异常”“生成失败”“无法打开系统分享面板”。错误提示说明书库仍在，可修复问题后重试。
- 页面和 `README.txt` 提醒：ZIP 是**未加密**的个人资料副本，可能含私人摘记、截图和封面；分享给别人等于分享这些内容。由用户决定保存位置和接收对象。
- 不上传服务器，不要求账号，不添加埋点；导出不自动公开到网络。

## 自动化测试与 iPhone 验收

- 纯序列化测试：中文、英文、emoji、换行／逗号／引号、CSV 公式开头文字；JSON 保持原文，CSV 可用普通解析器回读；日期未知仍为空。
- 数据快照测试：书、主角、类型、系统／自定义及快捷标签、评分、二刷、导入摘记的来源时间、封面与多处共用图片全部出现，ID 和排序不变；空书库文件也可打开。
- 归档测试：每个图片资产只出现一次，关系完整；图片缺失、文件不可读、路径不安全、重复图片 ID、包超限和写入失败均不交付半成品。
- 页面测试：入口、数量、忙碌态、错误、取消分享和重复点击；导出不调用恢复或导入写库操作。
- iPhone Expo Go：准备一部有二刷、多个主角／标签、多条摘记及共用图片的小说；从“数据管理”导出 ZIP 并保存到“文件”；在电脑解压，打开四个 CSV、`library.json` 和原图，核对中文、阅读日期、摘记与图片关系；再检查 App 中原书库没有变化。另测空书库与取消分享。真机完成前不得标注为已验收。

## 暂不包含

- 将开放 ZIP 直接导回 Novel Tracker、从 CSV 自动还原整个书库；需要回到 App 时仍使用 `.noveltracker` 专用备份。
- CSV／Excel 旧记录导入、截图 OCR、微博链接抓取、大模型联网补全。
- 自动备份、云同步、导出到固定第三方服务、加密、按书选择导出或隐私字段遮盖。

## 验收标准

1. 用户能在 iPhone Expo Go 中生成并分享标准 ZIP，电脑上无需安装 Novel Tracker 即可解压、查看表格、完整 JSON 和原图。
2. JSON 与图片完整表达当前书库全部资料和关联；CSV 能直接阅读主要书目、阅读历史、摘记及图片索引，缺失信息不被虚构。
3. 共用图片只打包一次，封面、精彩片段和摘记对它的引用都可追溯。
4. 图片缺失、空间不足、关联不合法或生成中途失败时，不提供残缺 ZIP，书库保持原样。
5. 导出与备份／恢复的入口、文件后缀和说明清楚区分；用户不会被引导用开放 ZIP 执行整库恢复。
6. 自动化测试覆盖格式、关联、文字转义、缺失图片和取消；iPhone 真机按上述步骤另行验收。
