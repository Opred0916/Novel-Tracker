# Novel Tracker — 摘记与精彩片段设计

日期：2026-10-02

## 目标

在现有书籍资料和多次阅读记录的基础上，增加可选的阅读摘记和“精彩片段”图库。一本书不要求必须有摘记；只有用户主动新增摘记时，才要求填写文字版“我的想法”。图片是摘记的可选补充，不代替文字。

摘记不要求用户手动填写“第几次阅读”。系统根据摘记创建时间和阅读历史的日期范围自动关联；无法可靠匹配时保留摘记并标记为未关联。精彩片段可以独立存在，也可以被摘记复用。

## 本次范围

### 摘记

- 一本书可以没有摘记，也可以有多条摘记；摘记按创建时间倒序展示。
- 每条摘记必须有“我的想法”文字。保存前对文字执行 `trim`，去掉空白后仍为空时拒绝保存并提示“请输入我的想法”。
- 摘记图片为可选项，可以不添加，也可以添加一张或多张截图。
- 摘记不再额外设置“说明”或“总评”字段；评分和整本书的总体资料仍属于书籍本身。
- 摘记支持新增、编辑和删除。删除必须二次确认；删除失败时不能从界面假装消失。
- 每条摘记展示创建日期、文字内容、图片缩略图，以及自动关联的阅读次数（例如“第 2 次阅读后”）。

### 精彩片段

- “精彩片段”是书籍级别的独立图片集合，不要求同时创建摘记。
- 用户可以一次从相册选择多张截图加入精彩片段，并按添加顺序展示。
- 用户可以从精彩片段中选择一张或多张图片附加到摘记；这不会复制图片文件。
- 用户也可以在写摘记时直接从相册选择图片。选择后提示：`是否同时加入“精彩片段”？`。选择“是”时，图片同时加入精彩片段和当前摘记；选择“否”时，仅附加到当前摘记。
- 精彩片段支持预览和删除。删除图库中的图片时，如果该图片仍被摘记使用，只解除图库关联，不删除摘记中的图片。

### 与阅读历史的自动关联

- 创建摘记时记录本地设备的创建时间，并取该时间对应的本地日历日期进行匹配。
- 对于有开始日期和结束日期的阅读记录，若摘记日期落在 `[开始日期, 结束日期]` 内，则认为摘记属于该次阅读。
- 对于仍在读的记录，若摘记日期不早于开始日期，则可关联到该次阅读。
- 多条阅读记录日期范围重叠时，选择阅读序号较大的那条匹配记录，保持与“最近一次阅读”直觉一致。
- 没有匹配记录时，摘记仍然可以保存，显示“未关联到具体阅读次数”；不强迫用户手动选择阅读次数。
- 编辑阅读记录日期后，系统重新计算相关摘记的自动关联；这不会修改摘记文字或图片。
- 旧书只有“日期未记录”的历史占位时，摘记不强行关联该占位记录。

## 数据与存储设计

当前项目使用 SQLite，数据库版本目前为 5。本功能使用一次可重复执行的迁移升级到下一个版本，不能覆盖或删除现有书籍、评分、标签、主角和阅读历史。

建议新增以下数据结构：

```text
image_assets
  id             TEXT PRIMARY KEY
  book_id        TEXT NOT NULL
  local_path     TEXT NOT NULL
  created_at     TEXT NOT NULL

notes
  id             TEXT PRIMARY KEY
  book_id        TEXT NOT NULL
  body           TEXT NOT NULL
  created_at     TEXT NOT NULL
  updated_at     TEXT NOT NULL
  reading_session_id TEXT NULL

note_images
  note_id        TEXT NOT NULL
  image_id       TEXT NOT NULL
  position       INTEGER NOT NULL
  PRIMARY KEY (note_id, image_id)

highlight_images
  book_id        TEXT NOT NULL
  image_id       TEXT NOT NULL
  position       INTEGER NOT NULL
  PRIMARY KEY (book_id, image_id)
```

- 图片文件保存到应用可管理的本地目录，数据库只保存稳定的本地路径和关联关系。
- 同一张图片可以同时属于精彩片段和一条或多条摘记；从精彩片段选择图片时只新增关联，不复制文件。
- 解除某个关联时，只有当图片不再被任何摘记或精彩片段引用，才清理本地文件和 `image_assets` 记录。
- 新增或编辑摘记时，文字、图片关联、可选的精彩片段关联应作为一次数据库事务提交。文件复制失败或数据库提交失败时保留表单输入，并清理本次产生的孤立文件。
- `body` 只存用户填写的“我的想法”，不把图片 OCR 结果混入正文。

## 页面与交互

### 小说详情页

在现有基本资料、评分和阅读历史之后，增加两个默认展开的区域：

1. **摘记**：显示摘记列表和“新增摘记”入口。每条摘记展示日期、自动关联结果、文字和图片缩略图，并提供编辑、删除入口。
2. **精彩片段**：显示图片网格和“添加图片”入口，支持多选相册、预览和删除。

书架卡片不显示摘记数量、图片数量或阅读次数，保持简洁。

### 新增／编辑摘记

- 页面标题为“新增摘记”或“编辑摘记”。
- 表单核心字段标签为“我的想法”，使用多行输入框。
- 文字下方提供“添加图片”入口：可从精彩片段选择，也可从相册选择。
- 保存按钮只有在“我的想法”去掉首尾空白后非空时才允许提交；图片没有选择也可以保存。
- 保存成功后返回详情页并刷新摘记、图片和自动关联信息。

### 图片权限与异常

- 用户拒绝相册权限、取消选择或暂时没有图片时，不崩溃、不清空已经填写的文字，并给出可理解的提示。
- 本地图片丢失时显示占位图和“图片不可用”，允许用户移除该引用；不能阻止文字摘记打开和编辑。
- 图片过大、复制失败或数据库保存失败时显示错误并保留输入，允许重试。

## 暂不包含

- 本次不实现 OCR、图片文字搜索或其他大模型能力。未来增加 OCR 时，使用独立的识别文本和搜索索引，不改变用户的“我的想法”原文。
- 不实现联网图片、云同步、账号、分享、阅读器、阅读时长统计或自动书籍简介。
- 不增加手动填写阅读次数的控件，也不增加独立的“开始本次阅读”“结束本次阅读”按钮。
- 不要求每次阅读必须有摘记，也不把摘记提升为书籍必填字段。

## 验收标准

- 一本书没有摘记时，详情页正常显示；用户可以只管理精彩片段。
- 新增摘记时，空白“我的想法”不能保存；填写文字但不加图片可以保存。
- 一条摘记可附加多张图片；同一本书可新增多条互不覆盖的摘记。
- 从精彩片段选择图片会复用同一图片；从相册添加时“是／否”提示分别产生正确的图库关联。
- 摘记创建日期在某次阅读范围内时显示正确的“第 N 次阅读”；无法匹配时显示未关联而不是阻止保存。
- 修改阅读日期后，摘记关联随之重新计算；修改文字或图片不会改变阅读历史。
- 删除摘记只删除其摘记关联；删除图库图片不会误删仍被摘记使用的图片。
- 数据库迁移可重复执行，旧书籍、评分、标签、主角和阅读历史完整保留。
- 自动化测试覆盖文字必填、图片可选、多图片关联、图库复用、相册同步提示、日期自动匹配、无匹配保存、删除引用保护和迁移兼容性。
- 真机验收至少包括：创建无图片摘记、创建带多张图片摘记、从精彩片段复用图片、相册图片选择“是／否”两种路径，以及跨阅读日期范围的自动关联。
