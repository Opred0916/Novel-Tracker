# Novel Tracker — 资料完善、表格导入与书库概览设计

日期：2026-10-03

## 目标与本轮边界

这一轮连续交付三项第一版功能：从 CSV／Excel 旧书单追加记录、为小说保存可选的“为什么想看”和阅读平台、查看基于真实记录的基础书库概览。它们共同服务于“把过去的书带进来、补全自己在意的资料、随时回看书架”。用户仍可只填书名；没有日期的旧记录保持日期未知。

本轮不做截图 OCR、联网书库、AI 简介、账号、会员、年度回顾、图表或进度统计。旧书单导入仍是追加，`.noveltracker` 恢复仍是整库替换，开放格式 ZIP 仍是只读副本。

## 方案选择与实施顺序

表格导入有两种易走偏的做法：按固定列名直接写库会误读用户的旧表；另造一套表格专属编辑流程会重复现有预览逻辑。因此采用“文件适配器 → 表格行 → 列对应 → 现有 `ImportCandidate` → 现有预览与原子提交”。Excel 与 CSV 只在文件读取和行解析处不同。用户确认列对应后才产生候选项。

资料字段先落到本地数据库，并打通新建、编辑、详情、导入、备份和开放导出；随后接入表格导入；最后增加只读概览。三个交付点各自可用，适合连续开发、逐项验证。

## 一、小说资料：“为什么想看”与平台

- `whyWantToRead: string | null` 表示用户自己的想看理由，不是摘记，也不代替读完后的感想；`platform: string | null` 表示用户填写的阅读平台名称，不绑定预置平台清单或网址。
- 新建、编辑均可留空、填写、修改或清除。首尾空白去掉，只有空白则存 `null`，内部换行与 Unicode 原样保留；不静默截断。平台建议一行输入，理由可多行输入。
- 数据接口中，新建时未传字段等于 `null`；编辑时未传字段表示保持原值，显式传 `null` 或空白才表示清除，避免旧调用方在升级后意外抹掉资料。
- 新建页在“想读”状态下展示想看理由，编辑页始终可查看和修改已有理由。状态从“想读”变为“在读／读完／弃读”时保留理由；详情页在有内容时显示，作为当初的记录。平台输入始终可用。书架卡片不增加这两项，以免拥挤。
- 两字段不参与现有书名／作者／主角／摘记关键词搜索，也不成为筛选项。下一轮若要搜索平台或想看理由，再明确修改搜索约定。
- SQLite `books` 增加可空列，旧库迁移默认 `null`，既有 ID、状态、日期和关系不变；普通创建与编辑一次保存时包含这些字段。
- 当前备份格式 3 升到格式 4，完整保存两字段；读取旧格式 1／2／3 时把缺失值规范成 `null`。新版备份恢复后两字段保真，旧版备份仍能恢复。开放格式 `library.json` 在 `books` 中加入两字段，格式版本升为 2；`books.csv` 增加 `why_want_to_read`、`platform` 两列并沿用现有公式防护，ZIP 的其他文件与图片关系不变。旧开放 ZIP 不支持 App 内恢复的既有约定不变。

## 二、CSV／Excel 旧书单导入

### 文件与工作表

- 在现有“追加旧记录”入口新增“选择表格文件”，接受 `.csv` 和 `.xlsx`。`.xls`、宏工作簿、在线表格链接及开放格式 ZIP 的反向导入不在本轮。文件选择取消保持页面与草稿不变。
- CSV 使用 UTF-8（可有 BOM）、RFC 4180 引号与多行单元格规则；预览中可选择逗号、分号或制表符分隔，不把嵌在引号里的分隔符当作列界。无法按 UTF-8 解码时明确提示改用 `.xlsx` 或另存 UTF-8 CSV，不替换坏字节。
- `.xlsx` 由纯 JavaScript 工作簿解析器读取，不引入 Expo Go 缺少的原生模块。多工作表时由用户选择一张；只读取单元格显示值，不运行公式、脚本或外部链接。公式单元格即使有缓存值也标为待处理，用户需手动核对或改填，避免使用过期计算结果。
- 读取前检查文件大小，CSV 最多 1 MiB，`.xlsx` 最多 5 MiB；单次最多 500 个非空数据行、100 列。超限提示分批导入，不截断。对 `.xlsx` 还需在工作簿解析前限制 ZIP 条目最多 1,000 个、声明和实际解压总量都不超过 25 MiB，避免小压缩文件耗尽手机内存。空表、仅有表头、损坏文件和不支持的编码都给出明确错误。

### 列对应与候选

- 默认第一行作为表头；若旧表没有表头，用户可切换“无表头”，以列 A、B、C…显示。先展示前五行原数据，按常见中英文列名建议对应关系，用户必须确认；建议不是自动保存。
- `书名` 是唯一必需对应列。可选对应列为作者、主角、阅读状态、总体评分、作品类型、标签、开始日期、结束日期、我的想法、想法原记录日期、为什么想看和平台。一个目标字段至多对应一列；用户可以明确忽略未对应的列，页面列出这些列，避免悄悄丢失。
- 一行形成一个候选书目。空白整行略过并计数；书名空白但其他列有内容的行进入待处理区，用户可补书名或明确忽略。重复书名的多行保留为独立候选，沿用现有重复提醒，不自动合并或把后一行变成前一行的摘记。
- 字段只按已确认列对应读取：状态接受现有中英文枚举，缺失时使用用户选定的整批默认状态；评分只接受 0.5～5 且半星递增，只有“读完”可带入；日期只接受完整有效年月日，未知保持 `null`。有明确阅读状态且不为“想读”时生成一条对应的历史阅读记录，不凭表格行号构造二刷。预览可核对这条记录的日期；同书多行不会自动合并成多次阅读，额外阅读次数可在入库后从详情页补记。
- 主角与标签的多个值使用页面明确选择的分隔方式；标签只匹配当前已存在的标签，无法匹配的文字作为行级待处理信息展示，不自动建系统标签。想法列的非空文字形成一条摘记候选；来源日期不明时不把导入当天当作原记录时间。想看理由和平台作为新书字段保存；选择“向现有书仅追加摘记”时不覆盖目标书的这两项。
- Excel 的数字日期通过工作簿单元格格式解读并显示 `YYYY-MM-DD` 候选；无法确定日期格式或遇到两位数年份时保留原单元格文本并要求人工修正。标题中的数字、序号和公式绝不自动当日期或评分。
- 表格候选进入现有 `ImportReview`；每项可修改、跳过、作为独立新书，或向现有书仅追加已确认摘记。提交前重新核对重复项及目标书，使用现有事务保证整批成功或整批回滚。原 CSV／XLSX 不被改写或删除。

## 三、基础书库概览

- 书架提供“书库概览”入口，进入只读页面。显示当前总书数、四种阅读状态各自的书数，以及“今年读完”书数；页面返回书架后，新增、编辑、删除或导入的结果可刷新显示。
- 总书数与状态数来自当前 `books` 表，同一书只属于一个当前状态，四项相加等于总数。
- “今年读完”按设备本地日历年计算，以 `reading_sessions.outcome='finished'` 且 `ended_on` 在当年为证据；同一本书当年完成多次只算一本。旧版只有 `legacy_read_count` 而没有确切结束日期的书、结束日期未知的导入记录均不计入。页面明确提示“仅统计记录了完成日期的书”。这项数字与当前状态无关：今年读完后又开始二刷的书仍计入。
- 不额外保存统计结果，不请求 AI，不从摘记文本推断完成时间。空书库显示 0 和引导添加／导入，查询失败可重试；页面获得焦点时重新查询，跨年后自然切换到新年份。

## 数据流与模块边界

1. 书籍仓储负责两个新字段的读写与迁移；导入提交服务只消费已核对的候选，不直接解析 CSV／XLSX。
2. `tableImportParser` 负责把 CSV／XLSX 变成有行号、列名和原值的二维表；`tableImportMapping` 负责列对应与候选转换；文件选择留在 Expo 平台适配层。三者均不写 SQLite。
3. 现有 `ImportReview` 继续承担重复提醒、人工修正和事务提交；若需容纳平台／想看理由，只扩展候选类型与对应表单字段，不改变旧 TXT 解析语义。
4. 概览由独立只读仓储执行聚合 SQL，页面只消费数量。备份和开放导出从同一新增字段读取，不另造第二份资料来源。

## 错误、隐私与兼容

- 文件格式、编码、大小、列对应、日期和评分错误在预览前或逐行显示；不因一行有错把整批直接写入，也不悄悄跳过非空数据。退出、取消选择、取消确认、解析失败或提交失败均不改变书库。
- 表格及摘记只在设备本地解析和保存，不上传服务器。开放导出是未加密副本，新增的想看理由和平台会随完整导出出现；页面继续提醒用户妥善保存。
- 新数据库版本、备份格式版本与开放格式版本分别演进；不能把其中一个版本号用于解释另一个文件。恢复旧备份时新增字段为 `null`，不能把“没有此字段”当成空字符串或虚构内容。

## 验收

1. 可新建一本只含书名的书，再填想看理由和平台；更改状态后理由不丢，编辑清空后再次打开仍为空。
2. CSV（含中文、emoji、引号、逗号与多行想法）和多工作表 `.xlsx` 经列对应与预览导入；未知日期不变成今天，重复书与未对应列需用户处理。
3. 取消表格导入、提交失败、损坏／超限文件均不新增记录；正常导入后书籍与摘记出现在详情、搜索、备份与开放导出中。
4. v4 备份保存并恢复两字段；v1／v2／v3 恢复仍可用。开放格式 v2 的 JSON 和 CSV 可读，字段内容一致且 CSV 公式防护仍有效。
5. 概览总数和四状态数吻合；今年读完按有确切结束日的不同书计数，二刷不重复计，日期未知不计；跨年与返回页面时刷新。
6. 自动化检查覆盖解析、映射、迁移、备份、导出、概览和关键页面；iPhone Expo Go 的选文件、表格预览和概览由用户真机验收，未实测不得标为通过。
