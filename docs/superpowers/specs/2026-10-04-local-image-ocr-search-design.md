# Novel Tracker — 本地图片文字识别与搜索设计

日期：2026-10-04

## 目标与本轮边界

让用户保存到“精彩片段”或摘记中的小说截图，能够凭截图里的文字从现有书架搜索框找回。识别在手机本地自动进行；图片和识别文字不发送到 OCR 或大模型服务。用户写的“我的想法”仍是摘记正文，机器识别文字只用于索引和说明搜索命中，不会伪装成用户感想。

本轮只做**已有书籍所关联图片的文字识别与检索**，不从截图自动创建书目、猜作者或标签，也不做语义搜索、AI 简介、云端识别、会员限制或全库联网。封面不参与识别：其主要用途是展示，不属于用户保存的阅读截图。

## 方案选择与交付前提

- **采用手机本地 OCR。** iPhone 优先使用 iOS Vision，经 Expo 本地原生模块暴露一个很小的识别接口；这样不需要服务端、API 密钥或按次调用费用。识别前需在设备上确认简体中文和英文可用，不能只凭接口存在就宣称中文已验证。Android 保留同一接口，未来可接本地 ML Kit；本轮不把尚未实现的 Android OCR 标为完成。
- **不采用“Expo Go + 在线 OCR”。** 这会上传用户截图，还需要服务、密钥保管、费用与隐私说明，和已经确定的“只在手机本地识别”不符。也不把未经真机验证的纯 JavaScript OCR 当成可交付方案。
- **原生识别不能在 Expo Go 中验证。** 加入本项目自定义原生模块后，需要安装专用 development build；其余不依赖该模块的现有功能仍须保持可用。Windows 上给 iPhone 安装 EAS 设备构建还需要可用的 Apple 签名凭据，这可能与当前零预算目标冲突；实施前应先核对是否已有可用凭据，不自动购买。若没有相应账号／凭据，文档与不依赖 OCR 的部分可以继续，但不能声称 iPhone OCR 已完成或已实测；取得签名条件后再做真机验收。原生工程继续按 Expo 项目配置生成，不手改或提交生成的 `ios/`、`android/` 目录。

## 图片范围与用户流程

1. 用户像现在一样从相册把一张或多张截图加到某本书的“精彩片段”，或作为摘记图片保存。图片成功落盘、关系成功入库后，系统为尚未识别的图片排入本地任务；保存书目／摘记不等待 OCR 完成。
2. 同一 `image_assets` 图片若同时用于精彩片段和多条摘记，只识别一次。仅附在摘记、未加入精彩片段的图片也应可搜索。与书关联但只作为封面的图片不排入任务。
3. 升级前已有的精彩片段／摘记图片、备份恢复得到的图片自动补入待识别队列。首次补录可逐张进行，页面显示“正在识别图片文字”及已完成／总数；退出页面或应用中断后下次继续，不重复处理已成功或已确认无文字的图片。
4. 识别失败不影响原图、摘记和搜索其他字段。图片位置在图库和摘记中照旧；失败项可在图片详情中点“重新识别”。图片没有可识别文字时记为“无文字”，而不是反复重试。
5. 用户输入截图中的一句话，书架仍按书为单位显示结果。若命中来自图片，卡片出现“匹配图片文字”及简短片段，不把它标成“匹配摘记”。点这条结果进入对应小说详情，并打开命中图片的预览；用户可看原图核对识别是否正确。

图库中普通点图也应能打开同一图片预览。当前 `HighlightsSection` 已预留 `onSelect`，详情页尚未接入；这属于本轮为“点搜索结果看到原图”补齐的交互，而不是增加新的图片编辑功能。

## 识别任务与本地数据

- 新增独立的识别适配接口，例如 `LocalImageTextRecognizer.recognize(localPath): Promise<string>`。仓储／搜索层只依赖接口与本地结果，不直接调用 Vision；在没有本地 OCR 能力的运行环境中明确显示“此测试方式暂不支持图片文字识别”，而不是导入原生模块后直接崩溃。
- SQLite 增加按 `image_id` 唯一关联的 OCR 记录，包含识别状态（`pending`、`processing`、`recognized`、`empty`、`failed`）、识别出的原文、完成时间、识别器版本及用于重试的简单错误类别。图片删除时级联删除 OCR 记录。`processing` 只代表本次运行；应用意外退出后可安全恢复为待处理。
- 排队扫描只针对仍被 `highlight_images` 或 `note_images` 引用的 `image_assets`。一次处理一张，在前台有限速执行，避免一次导入几十张图时卡住界面；应用进后台时暂停，回前台续跑。应避免同一图片因多个关联被重复入队。识别输入使用 App 已保存的本地图片，必要时生成临时缩小副本供识别，不改变或覆盖原图。
- 对中文优先配置 `zh-Hans`，同时兼顾英文；实际支持的语言由设备／Vision 请求能力检测并在真机验证。识别结果保留合理的换行；搜索时按现有规则进行大小写归一和连续文字包含匹配，不用翻译、自动纠错或推测语义代替原文。
- OCR 结果是**可重建的派生索引**。数据库版本从当前 v10 升级；现有备份格式 v4、开放导出格式 v2 暂不因索引而升级，也不把 OCR 文本额外写入这两种文件。原图片及其书籍关系按既有备份／导出规则保存；恢复后自动重建索引，重建完成前图片可能暂时搜不到。这样也避免在导出文件中再复制一份可能敏感的截图文字。未来若允许人工修订 OCR 文本，必须重新讨论备份与导出，因为那时它不再只是派生数据。

## 搜索规则与命中展示

- 沿用现有书架搜索框，提示扩展为“搜索书名、作者、主角、摘记或图片文字”。作品类型和标签仍只通过筛选控件选择；状态、类型及多个标签可继续与关键词组合。
- 继续采用现有“每个关键词都必须命中，但可分布在不同字段”的规则。一个词可命中书名，另一个词可命中某张图的 OCR 原文；图片未识别完成或识别失败时，不假装已命中。
- 在当前按书去重的结果结构中增加可选图片命中证据（`imageId`、`source`、短片段）；只有仍被当前书的精彩片段或摘记引用的图片才能作为证据。相同书有多张图命中仍只显示一张书卡，优先选稳定的一张证据，不能因 SQL 关联重复产生多本书。
- 书名／作者／主角已解释全部关键词时，可继续保持简洁；仅靠文字摘记命中时显示现有“匹配摘记”；有关键词靠 OCR 才满足时显示“匹配图片文字”。若关键词分别命中摘记和图片，也要保留图片入口，避免用户点开却找不到关键证据。
- 图片命中的跳转参数只传书 ID 和图片 ID。详情页重新核对图片仍属于这本书并确定是精彩片段还是摘记图片；若图片已删除或不再关联，正常打开书详情并提示“该图片已不存在”，不展示别的书的图片。普通搜索结果仍打开书详情。
- 搜索仍不匹配图片文件名、封面文字、标签名称、作品类型、首发平台或“为什么想看”。多词、特殊字符、中文、英文大小写、筛选叠加及查询竞态继续遵守现有搜索设计。

## 删除、失败、隐私与兼容

- 从“精彩片段”移除图片后，如仍被摘记引用，图片文字仍可作为这本书的搜索证据，但结果要指向摘记图片；若所有精彩片段和摘记引用都已移除，立即从搜索结果排除，并按既有清理流程删除不再使用的图片和 OCR 记录。仅剩封面引用时也不参与 OCR 搜索。
- 图片文件丢失、格式损坏、设备不支持相应语言、识别器出错或 App 中断都不能删除原有书目／摘记。失败状态保留可重试信息，但不记录完整图片路径到公开日志。批量处理不做无限自动重试；用户可手动重试。
- 不请求网络，不把图片、识别文字或图像特征传给外部服务；不在分析日志中记录 OCR 全文。备份／开放导出本来包含图片时，继续按现有未加密副本提示用户妥善保管。
- 新版数据库升级须保持旧书、摘记、图片和关联不变；旧备份仍能恢复。运行在 Expo Go 时，图片管理、书名／作者／主角／摘记搜索继续可用，只是 OCR 不执行，UI 不应误称“已识别”。

## 暂不包含

- 从截图识别书名、作者、主角、标签并建议建书；这需要独立的候选预览和用户确认流程，可复用本轮 OCR 接口，但不在本轮自动写库。
- OCR 文本人工编辑、图片内关键词高亮框、以图搜图、语义理解、翻译、搜索图片之外的附件，或跨设备同步 OCR 缓存。
- Android 本地 OCR 真机交付；先把接口和不支持时的行为设计好，后续再决定 Android 实现与验收。

## 验收标准

1. 在支持本地 OCR 的 iPhone 专用开发版中，离线添加中文和英文小说截图；图片保存后自动识别，无须再点“开始识别”。等待处理期间仍能操作书架和摘记。
2. 用截图中独有的一段连续文字搜索，可找到对应书，看到“匹配图片文字”摘要，点入后显示原图；只附在摘记中的图片也能找到。
3. 一张图被图库和多条摘记复用时只识别一次；移除其中一个引用后仍可搜索，全部引用移除后不再命中。封面文字不会带来关键词命中。
4. 多关键词跨书籍资料、摘记、OCR 文本匹配，叠加状态／类型／标签筛选，均保持原有语义；同一书多张图命中只返回一张书卡。
5. 老图片升级后自动补索引；恢复旧备份后图片关系保持且可重建索引；处理途中强退再打开可继续，失败项可重试，空文字不无限重试。
6. Expo Go 或无 OCR 模块时不崩溃、不上传图片，原有图文记录与非 OCR 搜索正常；页面说明为什么当前方式不能识别。
7. 自动化测试覆盖队列去重／恢复、状态迁移、图片引用与级联清理、搜索证据／去重、跳转参数校验和无原生模块回退。最终 iPhone OCR 成功与否必须以真实开发版的离线实测为准；若缺 Apple 签名条件，明确记录“未实测”，不能写成已通过。

- [Expo：Apple Developer Program roles and permissions for EAS Build](https://docs.expo.dev/app-signing/apple-developer-program-roles-and-permissions/)：iOS 实体设备构建的签名凭据要求。
