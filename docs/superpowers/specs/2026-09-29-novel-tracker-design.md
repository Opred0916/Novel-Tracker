# Novel Tracker 第一版产品需求总纲

初稿：2026-09-29；最新需求同步：2026-10-03。

本文件记录产品方向和第一版范围，不表示所有条目已经实现。已有功能的具体交互以对应的后续专题规格为准；新增功能实施前仍需单独确定边界并写开发计划。

## 1. 目标与边界

做一款私人的长期小说阅读档案。第一批用户是中文网文重度读者，但数据模型不把中文小说、中文平台或中文标签当成边界；未来可以服务其他语言的小说、同人和类型文学读者。产品优先解决“轻松记下、带入旧记录、多年后找回”的问题，不以计时、打卡或社交为核心。Codex 负责主要开发；用户负责产品选择与真机验收。第一阶段开发预算为零，优先完成离线可用的应用；将来争取通过 App Store 提供给其他人下载。

第一阶段使用 Expo / React Native 和 TypeScript。开发时通过 Expo Go 在 iPhone 上预览。Expo Go 不是独立发布版；独立安装、TestFlight 和 App Store 发布属于后续阶段，涉及 Apple 开发者会员及审核。第一版不设账号和服务器，不承诺自动跨设备同步。发布顺序是先做好中文版、验证真实使用，再制作英文界面并测试其他市场。

## 2. 用户场景

1. 听到安利时，只填书名也能加入“想读”；想记录“为什么想看”时，可选填一句话。
2. 开始阅读时，改为“在读”，记录日期；想到什么就能写一条简短感想，也可附图片。
3. 读完或弃读时，保留这次阅读的结果、日期与感想；整本书可选填总体评分。以后重读会形成新记录，不覆盖过去。
4. 回顾时，按书名、作者、主角或摘记搜索，并按状态、作品类型和标签筛选。
5. 首次使用时，可以把过去散落在文字、表格、截图等来源中的记录导入，先核对再保存到现有书库。
6. 随时备份和恢复，也能以开放格式完整带走自己的记录；私人内容默认不公开。

## 3. 第一版功能

### 3.1 书架

- 显示“想读、在读、读完、弃读”四种状态及各自数量。
- 每张书卡显示封面（未设置时为默认封面）、书名、作者、状态；有评分时显示评分。
- 支持按书名、作者、主角或摘记文字搜索；阅读状态、作品类型和一个或多个标签通过独立控件组合筛选，不作为关键词搜索字段。提供清除筛选入口；精彩片段的 OCR 文字待后续阶段接入同一搜索入口。
- 默认按最近修改时间排序；书架为空以及搜索无结果时给出明确提示。

### 3.2 小说资料

- 新增时只有书名必填，去掉首尾空白后不得为空；其他字段均可之后修改。
- 可选资料包括作者、多个主角、一个作品类型、多个标签、封面、阅读状态与日期，以及每半星一档的 0.5～5 星评分。想读时可选填一句“为什么想看”；平台信息也应允许用户自行填写，不强迫从中文平台列表中选择。
- 默认状态为“想读”；日期、评分、平台和想看理由均可留空。输入不合法时保留已填内容并显示针对性的错误。不为了统计要求用户额外填写阅读时长或进度。
- 每条小说具有稳定的内部 ID、创建时间与修改时间。书名相同可以分别建档，避免误合并同名作品。
- 为将来支持译名和原文名，书籍结构应能扩展为一个主要书名、多个别名与可选原语言；第一版可以先只展示主要书名，但新设计不得假定书名只有中文。

#### 作品类型与标签

- 作品类型为单选，初始提供“耽美、言情、GL、无CP、其他”；“其他”用于无法归入现有类型的作品，不要求用户新增类型。
- 标签为多选，用于补充故事设定、阅读体验和内容特点，例如“古代、现代、悬疑、无限流、群像、慢热、强强、HE”等。
- 添加书目时只展示用户配置的少量快捷标签；快捷标签列表可以在设置中编辑，决定哪些常用标签出现在新增表单中。
- 编辑书目时可以打开完整标签库，选择系统预设标签或用户自定义标签，也可以搜索、取消和新增标签。
- 从快捷标签列表移除标签，只影响新增表单的展示，不删除已经使用该标签的书。
- 标签和作品类型都允许留空；系统不强迫用户为每本书分类。

### 3.3 摘记、精彩片段与阅读历史

- 一本小说可以没有摘记，也可以有多条摘记；摘记不是每本书的必填资料，可新增、编辑和删除。
- 日常摘记由用户主动输入；未来的旧记录导入可以在预览确认后带入过去的感想，但应用不自动抓取阅读平台的原文。
- 同一本小说可以有多次阅读记录；每次记录有阅读序号、开始日期，在读时结束日期留空，结束后保存结束日期和结果。旧版记录若原本缺少日期，不凭空补造。
- 阅读次数不在书架卡片上显示，在详情页展示完整阅读历史。
- “我的想法”不是书籍级必填字段，而是摘记中的必填文字：只有新增摘记时才要求填写，去掉首尾空白后不能为空。新增摘记应支持一句话快速保存；章节、分类等补充信息不能成为保存前置条件。
- 摘记中的图片为选填，可以添加一张或多张；不添加图片也可以保存摘记。
- 摘记可以关联一张或多张图片；从相册添加图片时，用户可以选择是否同时保存到本书的“精彩片段”图库。
- “精彩片段”是每本书独立的图片库，支持批量上传、查看和删除；图片不设置单独说明文字，说明统一写在摘记的“我的想法”中。
- 同一张精彩片段图片可以被多个摘记引用；删除摘记不删除原图，删除原图前提示会同时从相关摘记中移除。
- 未来可为精彩片段增加 OCR 文字识别和搜索索引；当前阶段先保存原图，不把识别结果混入用户的“我的想法”。
- 摘记根据创建时间与各次阅读的开始/完成日期自动关联阅读次数；不要求用户手动填写。无法匹配时间范围的摘记标记为未关联。

### 3.4 阅读状态与进度

- 不记录已读章节、总章节数或百分比，不提供阅读进度条。
- “想读、在读、读完、弃读”描述用户自己的阅读经历；弃读保留在历史中，重读时不覆盖。作品连载状态不作为下一项开发功能，也不据此阻止用户标记“读完”。
- “追更、养肥、暂停”等在读附加状态是后续可讨论的轻量表达，不增加首页主状态数量；实施前单独确认交互和数据含义。

### 3.5 数据保存、导入与导出

- 小说资料、标签和摘记保存在设备本地；选中的封面复制到应用管理的文件位置，不只依赖相册原始路径。
- 数据修改后持久保存；应用重启后仍存在。删除一本书时同时删除其摘记和关联封面，先显示确认。
- **本 App 备份与恢复**：生成带版本号的单个备份文件，包含小说、阅读历史、摘记和用户图片；恢复前检查格式并明确提示将整体替换当前书库，失败不得破坏原数据。
- **旧记录导入**：第一版的核心体验之一，来源包括复制的文字、备忘录、微博记录、TXT、CSV／Excel 或其他 App 导出文件，以及截图。各来源可分期接入同一导入流程：识别候选记录、预览与编辑字段、提示重复项、逐项确认后写入现有书库；不能把“从本 App 备份整体恢复”冒充为旧记录导入。
- 多张本地截图导入的交互、保守识别规则与 Expo Go／专用开发版边界见[旧记录截图导入设计](2026-10-04-screenshot-old-record-import-design.md)；该文档是待实施方案，不代表截图导入已经可用。
- **开放格式完整导出**：除可恢复的专用备份外，让用户以通用格式取回书目、阅读历史、摘记、标签和图片等个人数据；具体文件组织和格式在独立设计中确定。不能只有应用私有的 `.noveltracker` 文件。
- 开放格式导出的文件结构、数据关联与验收细节见[开放格式完整导出设计](2026-10-03-open-data-export-design.md)。
- CSV／XLSX 旧书单导入、可选想看理由与平台、基础书库概览的下一轮边界见[资料完善、表格导入与书库概览设计](2026-10-03-library-enrichment-batch-design.md)。
- 导入管线接受 Unicode／多语言内容，不能预设来源文字一定是中文；识别不确定时保留用户确认和手工修正路径。
- 在 Expo Go 内卸载 Expo Go 或清除其数据会失去未导出的本地记录，因此产品内要明确提示主动备份。独立安装版发布时重新验证存储与恢复流程。
- Expo Go 与将来的独立 App 使用不同的本地存储；过渡前要从 Expo Go 导出，安装独立 App 后再导入，不能假设记录会自动转移。

## 4. 页面与流程

1. **书架**：状态切换、搜索与标签筛选、添加入口、进入详情。
2. **添加/编辑**：只填书名的快速路径，以及可选资料、日期、封面、评分和“为什么想看”。
3. **小说详情**：资料、阅读历史、随手感想／摘记、精彩片段、编辑及删除。
4. **导入**：选择已有记录来源，核对候选资料与重复项，确认后写入书库。
5. **设置与数据**：专用备份／恢复、开放格式导出、快捷标签配置和使用说明。

### 4.1 小说详情页

- 默认展开全部内容，不使用折叠区域隐藏资料。
- 页面顺序为：基本资料、阅读信息、阅读历史、摘记／随手感想、精彩片段图库。
- 书架卡片保持简洁，不显示阅读次数；阅读次数和完整阅读历史在详情页展示。
- 摘记和精彩片段分别在对应模块标题旁提供新增按钮；详情页底部提供编辑小说、添加摘记、上传精彩片段和删除小说等操作。

### 4.2 统计与回顾

- 统计只使用已有的真实记录，不使用 AI 猜测，也不要求用户为统计补填字段。
- 基础书库概览可在后续安排；统计页、年度回顾和分享卡暂不排在旧记录导入与开放导出之前。年度回顾应结合用户当时的感想，而不是只有数字。

### 4.3 大模型辅助录入（分阶段）

大模型只生成候选资料，不直接写入书库；用户必须在预览页核对、修改并确认后才保存。

### 分阶段接入：截图识别与可选联网补充

- 用户从相册选择阅读 App 截图。
- 大模型先识别截图中已经出现的书名、作者、平台、主角和可推断的题材标签。
- 识别结果进入可编辑的确认页，用户可以接受、修改或放弃。
- 用户可以选择“尝试联网补充资料”，根据书名和作者补充平台、主角、题材或封面等候选字段；不默认生成 AI 简介，具体资料来源和范围另行设计。
- 联网补充失败、无结果或网络不可用时，仍可使用截图识别结果或手动输入完成保存。
- 联网结果不能覆盖用户已经填写的内容；补充字段应标记为联网候选，并在保存前由用户确认。
- 识别可以作为旧记录导入的一个来源，但第一版不要求后台持续同步，也不自动抓取其他 App 的数据。

### 后续阶段：标签建议与个人推荐

- 可根据已确认的书籍资料建议分类标签，用户可逐项接受、编辑或跳过。
- 在书库数据足够后，再根据用户的标签、评分、状态和阅读记录，从合法可用的候选书目来源推荐未记录的小说，并解释推荐依据。
- 个人推荐需要单独评估数据来源、隐私、网络依赖、API 成本和版权/服务条款，不在当前录入功能中强行实现。

## 5. 技术设计方向

- Expo / React Native + TypeScript，先满足 iPhone；界面层、记录操作、存储与备份拆成清晰模块。
- 使用本地关系型数据库保存小说和摘记，并用应用文件目录保存封面。数据访问通过统一的仓储接口，避免页面直接依赖存储细节，为以后加入云同步保留接口空间。
- 正式发布前将用户可见文案集中到 i18n 资源；内部枚举使用与语言无关的值，日期和数字按设备 locale 格式化。平台和标签可扩展，导入与完整导出不绑定中文字段名。当前代码仍有直接写入组件的中文文案和固定中文日期控件，需要按阶段迁移，不能视为已完成国际化。
- 不在第一版引入账号、云服务、自动书籍检索、阅读器、计时器或社交功能。
- 如果将来面向大众发布，核心本地记录功能保持免费；AI 识别、联网书库、个性化推荐、云同步和高级统计等可能作为会员功能。会员、账号和支付不属于当前个人离线版本。
- 备份格式明确版本与编码，对外部导入数据设验证和错误提示；真实实现前确认所选 Expo SDK 的文件、图片、数据库和分享能力与 Expo Go 兼容。

## 6. 验收标准

1. 仅填书名可添加“想读”；退出并重新打开后记录仍在。
2. 可更改状态、作者、主角、作品类型、多个标签、封面、日期与半星评分；“为什么想看”和平台资料在对应功能完成后仍可留空，重新打开后资料保持。
3. 同一本书可添加、编辑、删除多条摘记，且其他摘记不受影响。
4. 搜索和筛选结果与记录内容一致；空列表和无结果有清楚的操作提示；作品类型和标签筛选互不混淆。
5. 专用备份导出后可以整体恢复；无效备份不会覆盖当前数据。开放格式导出需能让用户在本 App 之外读回完整个人记录。
6. 旧记录导入需先预览、修改并处理重复项；取消或解析失败不更改现有书库，不能静默覆盖用户资料。
7. 日期、评分及空书名输入错误有清楚提示；删除与整体恢复都需要确认。
8. Codex 运行针对数据、导入导出和备份的自动化测试；iPhone 核心流程由用户实机验收，并记录已知限制。

## 7. 交付阶段

1. **可运行纵向切片**：添加一本书、本地保存、重启仍可见。
2. **核心记录**：资料编辑、状态、标签、搜索与筛选。
3. **阅读内容**：摘记与精彩片段、评分、多次阅读日期、封面。
4. **数据归用户**：专用备份与恢复、开放格式完整导出、旧记录导入及真机试用修复。
5. **发布准备**：完善页面结构和 i18n，邀请试用，独立构建、隐私资料与 App Store 提交；取得需要的开发者资格后再执行。

## 8. 后续版本路线图

这些能力是已提出的产品方向，不属于第一版验收标准。第一版保持稳定的记录 ID、可扩展字段和版本化备份格式，避免后续升级时丢失旧数据；不为尚未选定的外部服务预先搭建账号或服务器。

1. **找回过去的记录**：在已有关键词搜索之外，评估基于用户资料与摘记的语义检索，结果应说明匹配依据；不能编造用户没有记录过的内容。
2. **回顾与主动分享**：年度回顾结合真实阅读历史和当时留下的感想；用户主动选择生成分享卡，私人书架不默认公开。
3. **个人口味推荐**：利用用户记录的标签、评分、状态和摘记建立偏好，再从合法可用的候选书目来源推荐未记录的小说。推荐需解释依据，允许用户反馈“不感兴趣”；候选数据来源、隐私处理与是否需要云服务在该阶段单独设计和评估成本。
4. **云同步**：账号、跨设备同步及冲突处理作为独立后续项目；第一版的本地仓储接口和导出格式为迁移提供基础。
5. **会员服务（仅面向未来公开版本）**：可将 AI 识别、联网书库、个性化推荐、云同步和高级统计作为付费服务；当前版本不实现账号、订阅或支付。

界面的具体视觉风格、图标和正式产品名称仍需在页面设计中确定。作品连载状态及其约束已被用户排除为当前下一项开发内容；若未来重提，再单独讨论。
