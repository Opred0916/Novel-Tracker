# Novel Tracker 第一版产品规格（待确认）

日期：2026-09-29

## 1. 目标与边界

做一款以网络小说为主的 iPhone 阅读记录 App。它帮助用户保存别人推荐、准备阅读的小说，并整理读过的小说、阅读摘记和读后评价。Codex 负责主要开发；用户负责产品选择与真机验收。第一阶段开发预算为零，优先完成离线可用的应用；将来争取通过 App Store 提供给其他人下载。

第一阶段使用 Expo / React Native 和 TypeScript。开发时通过 Expo Go 在 iPhone 上预览。Expo Go 不是独立发布版；独立安装、TestFlight 和 App Store 发布属于后续阶段，涉及 Apple 开发者会员及审核。第一版不设账号和服务器，不承诺自动跨设备同步。

## 2. 用户场景

1. 听到安利时，快速输入书名，加入“想读”，可补充推荐来源和想看理由。
2. 开始阅读时，改为“在读”，可记录开始日期、阅读平台，并随时写多条摘记。
3. 读完时，改为“读完”，填写读完日期、累计阅读小时数、1～5 星评分和一篇总评。
4. 放弃阅读时，改为“弃读”；已记录的内容保留，状态以后仍能修改。
5. 回顾时，按书名或作者搜索，按状态或分类标签筛选，打开详情查看感悟。
6. 换设备或清除应用前，主动导出备份；在新设备导入恢复。

## 3. 第一版功能

### 3.1 书架

- 显示“想读、在读、读完、弃读”四种状态及各自数量。
- 每张书卡显示封面（未设置时为默认封面）、书名、作者、状态；有评分时显示评分。
- 支持按书名或作者搜索，按状态和一个或多个分类标签筛选；提供清除筛选入口。
- 默认按最近修改时间排序；书架为空以及搜索无结果时给出明确提示。

### 3.2 小说资料

- 新增时只有书名必填，去掉首尾空白后不得为空；其他字段均可之后修改。
- 可选字段：作者、多个自定义分类标签、阅读平台、来自相册的封面、状态、推荐来源、想看理由、开始阅读日期、读完日期、累计阅读时长（小时，非负）、1～5 星整数评分、读后总评。
- 默认状态为“想读”；日期和评分均可留空。阅读时长手动录入，不提供计时器。输入不合法时保留已填内容并显示针对性的错误。
- 每条小说具有稳定的内部 ID、创建时间与修改时间。书名相同可以分别建档，避免误合并同名作品。

### 3.3 摘记与总评

- 一本小说可以有多条摘记；每条包含文本、可选的个人想法、创建时间，可新增、编辑和删除。
- 摘记由用户手动输入；不抓取阅读平台的原文，不自动导入。
- 一本小说有一篇可反复编辑的读后总评；评分和总评不强制绑定“读完”状态。

### 3.4 数据保存与备份

- 小说资料、标签和摘记保存在设备本地；选中的封面复制到应用管理的文件位置，不只依赖相册原始路径。
- 数据修改后持久保存；应用重启后仍存在。删除一本书时同时删除其摘记和关联封面，先显示确认。
- 导出生成带版本号的单个备份文件，包含所有小说、摘记及用户封面，可经 iOS 分享/文件界面保存到用户选择的位置。
- 导入先检查文件格式、版本与数据有效性，再展示记录数量和“将替换当前全部数据”的确认；导入失败不得破坏现有数据。第一版采用整体替换，不提供合并；建议恢复前先导出现有数据。
- 在 Expo Go 内卸载 Expo Go 或清除其数据会失去未导出的本地记录，因此产品内要明确提示主动备份。独立安装版发布时重新验证存储与恢复流程。
- Expo Go 与将来的独立 App 使用不同的本地存储；过渡前要从 Expo Go 导出，安装独立 App 后再导入，不能假设记录会自动转移。

## 4. 页面与流程

1. **书架**：状态切换、搜索与标签筛选、添加入口、进入详情。
2. **添加/编辑**：基本资料、封面、推荐信息、日期、小时数及评分；尽量保持快速新增只填书名的路径。
3. **小说详情**：资料和状态、阅读日期与时长、摘记列表与新增入口、读后总评和评分、编辑及删除。
4. **设置**：导出、恢复、数据位置与备份提醒、使用说明。

## 4.1 大模型辅助录入（分阶段）

大模型只生成候选资料，不直接写入书库；用户必须在预览页核对、修改并确认后才保存。

### 规划中的下一阶段：截图识别与可选联网补充

- 用户从相册选择阅读 App 截图。
- 大模型先识别截图中已经出现的书名、作者、平台、主角和可推断的题材标签。
- 识别结果进入可编辑的确认页，用户可以接受、修改或放弃。
- 用户可以选择“尝试联网补充资料”，根据书名和作者补充简介、主角、题材、完结状态、字数/章节数和封面等候选字段。
- 联网补充失败、无结果或网络不可用时，仍可使用截图识别结果或手动输入完成保存。
- 联网结果不能覆盖用户已经填写的内容；补充字段应标记为联网候选，并在保存前由用户确认。
- 第一版不要求后台持续同步，也不自动抓取其他 App 的数据。

### 后续阶段：标签建议与个人推荐

- 可根据已确认的书籍资料建议分类标签，用户可逐项接受、编辑或跳过。
- 在书库数据足够后，再根据用户的标签、评分、状态和阅读记录，从合法可用的候选书目来源推荐未记录的小说，并解释推荐依据。
- 个人推荐需要单独评估数据来源、隐私、网络依赖、API 成本和版权/服务条款，不在当前录入功能中强行实现。

## 5. 技术设计方向

- Expo / React Native + TypeScript，先满足 iPhone；界面层、记录操作、存储与备份拆成清晰模块。
- 使用本地关系型数据库保存小说和摘记，并用应用文件目录保存封面。数据访问通过统一的仓储接口，避免页面直接依赖存储细节，为以后加入云同步保留接口空间。
- 不在第一版引入账号、云服务、自动书籍检索、阅读器、计时器或社交功能。
- 备份格式明确版本与编码，对外部导入数据设验证和错误提示；真实实现前确认所选 Expo SDK 的文件、图片、数据库和分享能力与 Expo Go 兼容。

## 6. 验收标准

1. 仅填书名可添加“想读”；退出并重新打开后记录仍在。
2. 可更改状态、作者、平台、多个标签、封面、日期、小时数、评分和总评；重新打开后均保持。
3. 同一本书可添加、编辑、删除多条摘记，且其他摘记不受影响。
4. 搜索和筛选结果与记录内容一致；空列表和无结果有清楚的操作提示。
5. 导出后清空测试数据，再导入，记录、摘记和封面均恢复；无效文件不会覆盖当前数据。
6. 日期、小时数、评分及空书名输入错误有清楚提示；删除与覆盖都需要确认。
7. Codex 运行针对数据、筛选与备份的自动化测试，并在 iPhone 上完成核心流程的人工验收；记录已知限制和复现步骤。

## 7. 交付阶段

1. **可运行纵向切片**：添加一本书、本地保存、重启仍可见。
2. **核心记录**：资料编辑、状态、标签、搜索与筛选。
3. **阅读内容**：摘记、总评、评分、日期与时长、封面。
4. **可靠性**：备份恢复、错误与删除处理、测试、使用说明、真机试用修复。
5. **后续发布**：邀请试用、独立构建、隐私资料、App Store 提交；取得需要的开发者资格后再执行。

## 8. 后续版本路线图

这些能力是已提出的产品方向，不属于第一版验收标准。第一版保持稳定的记录 ID、可扩展字段和版本化备份格式，避免后续升级时丢失旧数据；不为尚未选定的外部服务预先搭建账号或服务器。

1. **截图识别录入**：从用户选择的阅读 App 截图中提取书名、作者、平台、主角和题材等候选信息；展示识别结果供用户核对、修改后才保存。可根据书名和作者选择联网补充简介、题材、完结状态、字数/章节数和封面等候选资料；联网失败时仍可手动完成录入。不同平台截图布局、图片权限和识别准确率需用真实样本验证；不自动抓取其他 App 的数据。
2. **旧记录导入**：支持用户从备忘录、微博或其他软件导出/复制的文本与文件中批量识别小说记录。先定义支持的来源与格式，再提供预览、字段映射、重复项提示和逐项确认；导入失败不改动现有书架。这与第一版“从本 App 备份文件整体恢复”是不同功能。
3. **个人口味推荐**：利用用户记录的标签、评分、状态和总评建立偏好，再从合法可用的候选书目来源推荐未记录的小说。推荐需解释依据，允许用户反馈“不感兴趣”；候选数据来源、隐私处理与是否需要云服务在该阶段单独设计和评估成本。
4. **云同步**：账号、跨设备同步及冲突处理作为独立后续项目；第一版的本地仓储接口和导出格式为迁移提供基础。
