# Novel Tracker — 全应用 iOS 风格 UI 重构设计

日期：2026-10-09。状态：用户已确认，可编写开发计划。

## 目标与边界

把现有中文版 Novel Tracker 调整为更接近 iOS 阅读与系统应用的界面：书架突出作品，录入和管理采用清晰的分组，内容页有稳定的导航、文字层级和操作位置。默认墨绿主题及现有八套主题颜色保留。改版后应能完成正式构建和真机验收，作为上架候选版本接受检查。

本轮只改呈现与交互容器，不修改小说、阅读历史、摘记、图片、标签、导入、备份及统计的数据模型或业务口径。不删除现有功能，不增加新的付费、同步、账户或 AI 功能。页面上的已有入口可以调整位置和样式，但必须仍可到达。现有路由和三栏信息架构原则上沿用；若为修复返回路径需微调导航配置，不改变目的页面。

本设计覆盖书架、添加与编辑、小说详情、阅读日期、摘记与精彩片段、回顾及分享、管理、标签、导入导出、备份恢复、外观与数据安全等现有页面。它取代 `2026-10-04-navigation-and-visual-refresh-design.md` 中与新版页面布局冲突的视觉和字段顺序描述；该文档中已经确定的功能规则继续有效。此前文字示意图中的详情折叠卡片只是层级示意，正式版不默认折叠阅读记录、摘记等内容。

## 设计方向

采用“书库感 + 系统式操作页”：书架以封面、书名和作者为主；表单、设置及选择器采用 iOS 常见的分组列表、导航栏、底部面板和明确的完成操作。保留低饱和暖纸白背景、白色内容面、深色正文，以及当前主题色作为操作与选中颜色。主题色不替代评分金色、错误和删除色，也不大面积填满每张书卡。

页面整体层级统一为：系统状态栏和安全区 → 当前页面标题/返回与操作 → 主要内容 → 底部栏或当前任务的主操作。顶部标题不得与状态栏重叠；页面内不同时出现两套大标题。子页面返回文案用“书架”“小说详情”“管理”等用户可理解的名称，不出现 `(tabs)` 或路由文件名。

## 共用视觉与交互规则

- 建立一套供现有页面共用的间距、字号、圆角、分隔线和行高规则。标题、区段标题、正文、说明与错误各有固定层级；避免每页独立定义近似但不一致的尺寸。
- 导航栏、三项底部栏、搜索框、分组行、封面、状态选择、标签选择、主要按钮、次要操作、底部面板和空状态共享视觉规则。相同含义的“选中”在全应用使用当前主题色、形状/勾选和无障碍状态共同表达。
- 常规列表行至少提供容易点击的整行区域；纯图标操作有文字标签或无障碍名称。禁用、按下、加载和错误状态可辨。文字放大时允许换行或滚动，不通过缩小文字挤进固定宽度。
- iPhone 安全区、横向窄屏、键盘与底部 Home 指示条均留有空间。页面滚动到底部后，最后一个输入框和保存按钮可见；底部面板在键盘弹出时仍可操作。
- 页面优先使用系统导航、可访问的输入和选择行为；仅在现有能力要求下保留自定义封面、评分、标签及回顾卡片。iOS 风格是视觉和交互目标，不复制 Apple 应用的图标或专属素材。
- 继续支持现有八套主题。每页使用 `ThemeProvider` 的语义色，不把墨绿写死在组件里。现有主题存储键和已选主题不变。系统深色外观与动态字号要检查可读性；如本轮维持浅色配色，应让应用实际显示与配色一致，不能在系统深色模式下出现黑色背景和浅色卡片混搭。

## 三栏导航与书架

底部维持“书架、回顾、管理”。选中图标和文字使用主题色，未选中项使用中性灰；页面与底部栏之间有细分隔。子页面不显示重复底部栏。回到三栏时保留合理的当前位置和已输入的书架查询条件，具体行为以现有导航和搜索状态为准。

书架顶部只保留“我的书架”这一主标题。搜索框、五个阅读状态（全部、想读、在读、读完、弃读）和紧凑工具区形成清楚的顺序；状态仍是一级分区，数量仍显示，窄屏可横向滚动。“排序、筛选、更多”作为同一行的次级入口，其中“更多”继续容纳批量整理与随机想读。排序、类型和标签的现有规则、搜索范围及空结果处理不变。只切换阅读状态时不出现“清除筛选”；筛选条件存在时显示条件数量，并在面板内重置。

书目采用更紧凑的白色列表行/轻卡：左侧封面，中央书名和作者，右侧可选评分；搜索命中摘记或图片文字时保留命中摘要。默认封面继续展示书名，真实封面保持比例与裁切规则。只在“在读”分区保留快捷记录入口；批量模式继续提供选择、全选当前结果、整理所选与取消。新增小说的主操作固定于底部安全区之上，列表末项不被遮挡；进入批量模式时按现有规则隐藏该操作。

加载、空书库、无筛选结果和读取失败各有独立提示。首次使用卡片、随机想读面板及书架错误重试仍可进入，避免 UI 收拢后失去功能入口。

## 添加与编辑小说

两页使用相同的字段和分组样式，但保留各自现有的保存、日期和状态转换规则。新增页顶部为一块容易操作的“封面 + 书名”区域：封面预览/默认书名封面始终可见，点按后可从相册选择、粘贴 HTTPS 图片链接，已有封面可移除；下载、失败与取消沿用现有逻辑。书名仍是新增小说唯一必填项，保存入口始终清晰。

封面与书名下方的基本信息组依次放作者、首发平台、主角名字。作者与首发平台仍可输入新值或选用书库中的历史建议。主角默认提供两个输入位，可继续添加任意个；长列表随表单滚动，输入第二个及之后的名字时键盘不能遮挡当前字段。

阅读信息组放阅读状态以及随状态出现的字段：“想读”可填写“为什么想看”；“在读、读完、弃读”的日期按现有规则出现；“读完”显示可选半星评分。编辑已有书时，已保存的“为什么想看”和评分按现有规则保留可访问，状态切换不清空暂时隐藏的草稿。改变在读状态所触发的阅读记录、日期默认值及确认弹窗保持原逻辑。状态选择的选中样式与作品类型、标签保持一致。

分类标签组放作品类型、快捷标签和“全部标签”入口；全部标签的搜索、多选与新建自定义标签功能保留。新增页不设置“低频内容”“其他资料”或“更多信息”分组，也不把封面藏进尾部。表单顺序以实际操作方便为准，不把没有填写的选填项误标为必填。

保存时的加载、校验错误、重复点击保护和未保存内容返回处理沿用现有业务逻辑；页面展示错误应靠近相关输入或保存区，不清空已填内容。编辑页仍能访问全部现有字段与封面操作，不减少资料编辑能力。

## 小说详情与阅读记录

详情顶部集中呈现封面、书名、作者、阅读状态和可选评分，并保留“编辑小说”入口。下方用清晰的区段展示作品资料、阅读历史、摘记和精彩片段；这些内容默认展开，用户向下滚动即可查看完整记录，不要求逐项点击进入。资料区继续显示首发平台、主角、作品类型、标签与“为什么想看”（有内容时）；缺失项按现有规则提示或省略。

阅读历史仍按第几次阅读展示日期与结果，可进入补记首刷日期或编辑某次阅读。摘记继续以“我的想法”为必填，图片选填，支持从精彩片段选取或从相册加入；精彩片段支持多图、图片预览与本地文字识别状态。详情中搜索定位到摘记或图片的跳转、重试、删除确认与数据安全处理保持可达。主要操作可以用紧凑操作行呈现，但不得把添加摘记、添加图片、补日期或编辑入口藏到不可发现的菜单里。

阅读日期页、摘记表单、图片预览和在读快捷记录面板沿用共用表单/底部面板样式；日期滚轮仍按数字年、月、日顺序呈现。不要以 UI 重构为由改变阅读次数、自动关联、OCR 搜索、评分或日期校验口径。

## 回顾、管理与数据操作

回顾首页先显示现有书库概览的核心统计，再以分组行或预览卡进入年度总结、年度阅读回顾与主题回顾卡片。现有年份、统计去重、故事页、海报、分享和空数据流程不变。分享图片的最终视觉可继续使用现有独立样式，但进入和返回路径、按钮及加载/错误反馈与新 UI 一致。

管理首页采用紧凑分组列表：标签与分类、数据管理/旧记录导入、导出与备份、数据安全、外观。现有“快捷标签设置”“数据管理”“追加旧记录”“导出开放格式”“备份与恢复”“使用与数据安全”“主题颜色”等入口全部保留，可按组内主次减少重复按钮。管理页不重复陈列回顾内容；若旧“书库概览”入口仍保留，则链接到同一回顾页面而不复制统计实现。备份提醒仍按现有时机出现，不能因改版消失。

导入来源（文字/TXT、表格、截图）、识别与字段映射、逐条预览、重复项处理、导入完成统计继续完整展示。备份、恢复、开放格式导出及数据安全说明保留原确认和错误流程；破坏性恢复使用明确警示样式。标签和外观页面采用分组行及当前选择反馈；八套主题预设仍可即时预览并保存。

## 实施边界与验收

先抽取可复用的 UI 基础样式与组件，再逐页替换外层布局；业务状态、仓储和数据库代码保持原位。优先顺序为导航/安全区 → 书架 → 添加与编辑 → 详情及记录 → 回顾 → 管理和导入导出。每一批完成后核对入口和数据流程，避免一次改动全应用而难以定位回归。

验收需要覆盖以下可观察结果：

1. 八套主题中至少默认墨绿与两套对比明显的预设在书架、表单、详情、回顾、管理和底部面板保持文字可读；主题切换后页面不残留硬编码墨绿。
2. iPhone 状态栏、导航栏、键盘、底部栏与 Home 指示条不遮挡内容；小屏和文字放大时仍能完成添加、编辑、筛选、摘记、导入与恢复确认。
3. 新增页封面与书名一眼可见，作者、首发平台和多个主角位于同一基本信息组；不存在“低频内容”分组。只填书名仍能保存；相册/链接/默认封面都可用。
4. 书架五状态、搜索、排序、筛选、批量整理、随机想读和在读快捷记录入口完整，筛选和选中反馈明确；搜索命中摘记和图片文字仍可定位到详情。
5. 详情各内容区默认展开，阅读历史、摘记、精彩片段、编辑与删除可达；现有阅读日期、评分和记录关联规则不变。
6. 回顾统计与分享、管理全部入口、标签、三类导入、导出、备份和恢复均有完整路径；导入/恢复的确认和失败提示不会被视觉改版省略。
7. 自动化验证聚焦现有业务回归、路由和关键 UI 状态；通过 lint、类型检查及必要的功能测试后，在 iPhone 真机对关键流程和视觉做人工验收。由于 `app.json` 当前声明支持 iPad，也要确认 iPad 布局或在发布配置中作出明确决定。

本设计完成后的“可上架候选”表示 UI 和现有功能通过验收。正式上架还需要独立完成生产构建、签名、App Store Connect 资料、隐私说明、真机安装与审核；这些发布工作不由 UI 改版测试自动替代。
