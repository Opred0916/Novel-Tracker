# Novel Tracker — 小说详情与编辑设计

日期：2026-10-01

## 目标

在已可运行的第一版上，让用户从书架打开一本小说，查看并修改书名、作者、阅读状态和主角名字。主角可有任意多个；编辑时默认显示两个名字输入框。升级必须保留现有书架记录。此阶段仍以 Windows 开发、iPhone Expo Go 验收和离线本地保存为准。

## 本次范围

- 书架卡片可进入小说详情页；书架显示记录的真实阅读状态，不再统一显示“想读”。
- 详情页显示书名、作者、阅读状态和按输入顺序排列的主角名字，提供“编辑”入口。
- 编辑页可修改书名、作者、阅读状态及主角名字。书名必填；其余字段可留空。主角区域至少显示两个输入框，可继续添加，也可清空已有名字。
- 保存时去除各输入值首尾空白，不保存空白主角名字。保存成功后返回详情页，书架与详情页均显示更新后的信息；保存失败时保留用户输入并显示错误。
- 快速新增保持“只填书名即可保存”的路径，不强迫新用户填写作者或主角。

## 暂不包含

二刷／三刷记录、评分、摘记、封面、标签、搜索、删除、云同步和备份恢复不在本次更新中。二刷／三刷将在后续更新中采用“每次阅读一条记录，分别保存日期和感想”的设计，而不只存一个次数。

## 数据与兼容性

- `Book` 增加可为空的作者以及按顺序保存的主角名字列表。已有书名、状态、稳定 ID 和时间戳继续保留。
- SQLite `books` 表增加可为空的作者字段；主角名字存入与书籍 ID 关联、带顺序位置的独立表，而非用分隔符拼成一个字符串。这样可保存任意数量，也不会因名字包含标点而解析错误。
- 数据库升级应可重复执行；已有小说默认作者为空、主角列表为空，旧记录不得被重建或覆盖。编辑时虽显示两个空输入框，但它们不会变成虚构的主角记录。
- 仓储接口增加更新小说的操作。一次保存同时更新书籍字段和主角列表；任何一步失败，都不应留下只更新了一部分的数据。成功修改时更新 `updatedAt`，保持 `createdAt` 和 ID 不变。

## 页面流程与错误处理

1. 用户在书架点击卡片，打开对应详情页。若记录不存在，显示明确提示和返回书架入口。
2. 点击“编辑”进入预填现有数据的表单。已有主角超过两个时全部显示；不足两个时补足空输入框。
3. 用户可继续添加主角输入框。清空名字后保存即删除该主角；原有名字顺序保留。
4. 空白书名阻止保存并提示原因。读取或保存数据库失败时显示可重试的错误，不丢失表单内容，也不显示错误的成功状态。
5. 详情页和书架在返回前台或重新打开时重新读取本地数据，展示最新内容。

## 验收

- 从第一版升级后，原有小说仍在，书名、状态、ID 和创建时间不变。
- 可编辑书名、作者和四种阅读状态；退出并重新进入 Expo Go 后内容仍在。
- 可保存零个、一个、两个及三个以上主角；空输入框不形成记录，顺序不乱。
- 空书名及存储失败不会覆盖旧数据；失败后输入仍可继续修改并重试。
- 自动化测试覆盖数据库升级、仓储更新与主角列表持久化、表单校验和书架状态显示；运行测试、TypeScript 类型检查及 lint。最后请用户在 iPhone Expo Go 验证核心流程。
