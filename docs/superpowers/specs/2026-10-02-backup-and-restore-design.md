# Novel Tracker — 备份与恢复设计

日期：2026-10-02

## 目标

为当前离线书库提供可靠的手动备份与完整恢复能力。用户可以把书籍、标签、阅读历史、摘记和图片导出为一个文件，并在清除 Expo Go 数据、换手机或后续安装独立版本时恢复。

本次恢复采用“完整替换”：先对备份包做完整验证，再向用户展示预览并二次确认；只有全部文件和数据可用时才替换当前书库。验证失败、用户取消或恢复提交失败时，当前数据保持不变。

## 本次范围

### 完整备份

- 从设置页手动导出完整备份。
- 备份包含小说、主角、作品类型、标签与快捷标签、状态、评分、多次阅读记录、摘记、精彩片段图片和所有关联。
- 空书库也可导出有效备份，便于验证格式和测试恢复边界。
- 导出前检查所有被引用的图片；应有图片缺失或无法读取时导出失败，不生成看似成功的残缺备份。
- 生成后打开 iOS 系统分享面板，用户可保存到“文件”、隔空投送或选择其他分享目标。

### 完整恢复

- 通过系统文件选择器选取 `.noveltracker` 备份包。
- 恢复前先解析到临时目录，检查格式版本、字段、记录 ID、数据关联、图片完整性和安全路径，不在验证阶段修改当前书库。
- 验证通过后展示备份时间和书籍、阅读记录、摘记、图片数量，再明确提示“恢复后将替换当前全部数据”。
- 用户确认后才进行完整替换；不提供部分恢复、跳过错误或与当前书库合并。
- 恢复成功后返回书架并刷新仓储状态，不要求用户手动重启 App。

## 备份文件格式

导出一个后缀为 `.noveltracker` 的版本化单文件。文件内部为可校验的压缩归档，不直接复制 SQLite 数据库：

```text
novel-tracker-backup.noveltracker
├── manifest.json
└── images/
    ├── <image-id-1>.<ext>
    ├── <image-id-2>.<ext>
    └── ...
```

### `manifest.json`

第一版备份格式使用 `formatVersion: 1`，并包含：

- `exportedAt`：ISO 8601 导出时间。
- `appVersion`：生成备份的 App 版本，仅用于问题诊断，不代替备份格式版本。
- `counts`：小说、阅读记录、摘记和图片等数量，供恢复预览和完整性交叉检查。
- `books`、`protagonists`、`tags`、`bookTags`、`quickTags`、`readingSessions`、`notes`、`noteImages`和 `highlightImages` 等版本化数据集。
- `images`：图片 ID、所属书籍、创建时间、文件扩展名、字节大小和包内相对路径。

备份不保存设备上的绝对 `localPath`。恢复时为图片生成新的 App 内部路径，再把它写入数据库。

### 图片去重与关联

- 每个 `image_assets` 记录在 `images/` 中只保存一份文件。
- 同一张图片可同时属于精彩片段和一条或多条摘记，通过图片 ID 恢复所有关联，不重复打包。
- 包内目录只允许 `manifest.json` 和声明过的 `images/` 文件。拒绝绝对路径、`..` 跳转、重复文件名、超出声明数量或解压安全限制的归档。

## 导出流程

1. 用户进入“设置 → 备份与恢复”，查看当前书籍、阅读记录、摘记和图片数量。
2. 点击“导出完整备份”后，页面进入忙碌状态，禁止重复操作和同时修改数据。
3. 备份服务读取一致的 SQLite 数据快照，验证每个图片引用，然后在临时目录生成备份包。
4. 生成成功后打开系统分享面板。页面可记录“上次生成备份”时间，但不声称外部文件已被用户成功保存。
5. 分享完成或取消后清理本次临时文件，不删除用户在系统分享目标中保存的副本。

## 验证与恢复流程

1. 文件选择器把用户选择的包交给备份服务；用户取消选择时不显示错误。
2. 备份服务将内容解析到新建的临时目录，验证归档路径、格式版本、JSON 结构、字段取值、唯一 ID、外键关联、数量和每张图片。
3. 对于高于当前支持版本的备份，明确提示“备份格式版本过新，当前 App 无法读取”；不尝试降级或部分导入。
4. 验证通过后生成只读预览，展示备份时间与主要数量；用户仍可取消。
5. 用户确认替换后，先把全部图片复制到一个新的恢复分代目录。任一图片失败时删除该临时分代，当前数据不变。
6. 图片就绪后，在一次 SQLite 事务中按外键安全顺序替换所有数据，并写入新的图片内部路径。事务失败时回滚数据库并删除新图片分代。
7. 数据库提交是恢复切换点。提交成功后，新书库立即可用；旧图片目录在后续安全清理。如清理失败，不回退已可正常使用的新数据，而是在下次启动重试清理未引用文件。
8. 恢复成功后清理解析目录，刷新页面和仓储状态。

## 数据验证规则

- 必须是支持的备份格式版本，所有必填数据集都存在且类型正确。
- 书名和摘记正文遵守当前的非空约束；阅读状态、作品类型、评分和阅读结果必须位于支持范围。
- 日期和时间必须符合对应字段格式，阅读结束日期不早于开始日期。
- 每类记录的 ID 必须唯一；图片、标签、书籍、摘记和阅读记录的关联必须指向存在对象。
- 数量摘要必须与实际数组和归档条目相符。
- 每张声明的图片都必须存在，字节大小与声明一致，且不得有未声明的额外归档条目。
- 归档解压前先检查条目数、声明解压大小、路径和可用存储空间；达到安全上限时整体拒绝，不继续尝试。具体上限在实施计划中根据 Expo Go 可用文件 API 和真机验证结果固定并测试。

第一版固定安全上限为：归档条目总数不超过 20,001（一个 manifest 加最多 20,000 张图片），`manifest.json` 解压后不超过 10 MiB，全部条目解压后不超过 2 GiB，且恢复前必须预留足够容纳解压临时文件、新图片分代和安全余量的可用空间。后续只能通过新的备份格式或明确兼容规则调整这些上限。

## 页面与状态

新增“备份与恢复”设置页，包含：

- 当前书籍、阅读记录、摘记和图片数量。
- “上次生成备份”时间，无记录时显示“尚未生成备份”。
- “导出完整备份”与“从备份恢复”两个主要操作。
- 说明备份可能包含私人摘记和截图，需由用户妥善保管。

处理期间页面显示“正在整理数据”、“正在打包图片”、“正在验证备份”或“正在恢复数据”等阶段，并禁用导出与恢复按钮。用户取消文件选择或分享时安静返回，不显示失败。

## 错误处理

页面需区分并给出可理解的提示：

- 选择的文件不是 Novel Tracker 备份。
- 备份格式版本过新，当前 App 无法读取。
- 备份文件损坏、内容不完整或数据关联无效。
- 备份包超过安全限制或手机可用存储空间不足。
- 图片缺失、无法读取或无法写入。
- 导出失败；恢复失败时同时明确“原有数据未发生变化”。

所有临时目录使用每次操作的随机 ID 命名，并在成功、取消或失败后清理。启动时可安全删除不再被引用的历史临时目录。

## 代码边界

- `backupFormat`：定义 `formatVersion: 1`、manifest 类型、字段与关联验证，不读写 SQLite 或文件系统。
- `backupArchive`：生成和解析 `.noveltracker` 归档，负责路径、条目、大小和完整性安全。归档实现必须与 Expo Go 兼容，不引入需要自定义原生客户端的依赖。
- `backupRepository`：从当前库组装 manifest 数据，提供数据概览，并以一次 SQLite 事务完成验证后的数据替换。
- `backupFileStorage`：处理临时目录、图片分代、文件复制和安全清理，不解析业务数据。
- `BackupRestorePage`：调用备份服务，展示概览、进度、恢复预览、确认和错误，不直接执行 SQL。

文件选择和系统分享分别使用项目已安装的 `expo-document-picker` 与 `expo-sharing`。归档使用纯 TypeScript 的 `fflate` 流式 ZIP 接口；`manifest.json` 可压缩，已经压缩的 JPEG、PNG 和 HEIC 图片使用 ZIP pass-through，避免无效的二次压缩。Expo SDK 57 的 `expo-file-system` 提供 `FileHandle.readBytes()`、`writeBytes()` 和可用空间信息，导出和导入以分块方式在文件与归档流之间传递，不把整个备份或全部图片同时读入内存。

实施计划在写入完整归档层之前，先用 Expo Go 完成一个最小垂直验证：流式写入含 manifest 和一张图片的包，经系统分享保存，再由文件选择器读回并校验字节。该验证使用最终选定的 API，不保留独立的临时实现。

## 自动化测试

- 空书库可导出并恢复。
- 书籍、主角、类型、标签、快捷标签、状态、评分和稳定 ID 完整保留。
- 多次阅读记录、日期、结果、摘记文字与创建时间完整保留。
- 同一图片被精彩片段和多条摘记共用时，只导出和恢复一份文件，关联全部正确。
- 导出遇到缺失图片时失败，不产生残缺包。
- 非法格式版本、损坏归档、重复 ID、缺失关联、未声明文件、危险路径和超出安全限制均被拒绝。
- 图片复制失败或 SQLite 事务失败时，旧数据库和旧图片仍可正常使用。
- 选择文件、分享、恢复预览或最终确认的取消路径不写入数据。
- 恢复后书架搜索、筛选、详情、阅读历史、摘记和精彩片段依然正常。

## iPhone Expo Go 验收

1. 创建包含多本小说、至少一本二刷记录、多条摘记和多张共用图片的测试书库。
2. 导出 `.noveltracker` 备份并通过分享面板保存到 iOS“文件”。
3. 修改当前书库，使恢复前后差异明显；再选择该备份，检查恢复预览数量并确认替换。
4. 逐项检查书籍、标签、阅读日期、阅读次数、摘记、精彩片段图片和图片共用关联。
5. 检查恢复后的书名／作者／主角／摘记搜索和状态／类型／多标签筛选。
6. 尝试选择一个普通 JSON、损坏包或过新版本包，确认提示清楚且当前数据不变。

## 暂不包含

- 自动定时备份、后台备份和系统通知提醒。
- iCloud 自动同步、账号、云端存储、设备间冲突解决和多备份版本管理。
- 选择部分书籍导出或恢复。
- 备份与当前书库合并、去重提示和字段冲突处理。
- 备份密码、端到端加密或公开分享链接。
- 从其他小说 App、备忘录或社交平台导入记录。

## 技术依据

- [Expo FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/)：Expo Go 内置，提供文件字节、`FileHandle` 分块读写和可用磁盘空间。
- [fflate](https://github.com/101arrowz/fflate)：纯 JavaScript／TypeScript ZIP 实现，提供流式创建和解析归档的接口，不依赖自定义原生模块。

## 验收标准

- 可将当前全部数据和图片导出为一个有明确格式版本的 `.noveltracker` 文件。
- 备份包中共用图片仅保存一份，恢复后的摘记和精彩片段关联不丢失。
- 恢复前完整验证并显示备份时间和主要数量，未经二次确认不替换当前数据。
- 验证失败、文件复制失败或数据库事务失败时，当前数据仍完整可用，且临时文件被清理。
- 恢复不会生成重复记录；当前书库被验证过的备份内容完整替换。
- 备份与恢复可在当前 iPhone Expo Go 环境中使用，不要求定制 development build。
- 自动化测试覆盖完整往返、共用图片、非法包、取消、回滚和恢复后现有功能。
- iPhone 真机验收完成一次保存到“文件”的导出和一次完整替换恢复，并确认无效文件不会覆盖当前数据。
