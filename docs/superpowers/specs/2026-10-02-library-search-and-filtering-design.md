# Novel Tracker — 书库搜索与组合筛选设计

日期：2026-10-02

## 目标

让用户在书库逐渐变大以后，仍能快速找到已经保存的小说。搜索覆盖书名、作者、主角、作品类型、标签和摘记中的“我的想法”；阅读状态、作品类型和多个标签可以与关键词叠加筛选。全部查询在本地完成，不需要联网。

当前书架已经支持在内存中搜索书名、作者和主角，也能按状态、类型和标签筛选。本次把查询下沉到 SQLite，并补充标签、作品类型和摘记文字搜索，同时保留现在熟悉的书架入口与筛选交互。

## 搜索范围

关键词可以匹配以下内容：

- 小说书名。
- 作者名字。
- 任意一个主角名字。
- 作品类型的中文名称，例如“耽美”“言情”“无 CP”。
- 任意已关联标签，包括系统标签和用户自定义标签。
- 任意一条摘记中的“我的想法”文字。

本次不搜索阅读日期、阅读次数、评分、图片文件名或精彩片段图片内容。OCR 识别文字将在后续阶段接入同一搜索入口，但不属于本次范围。

## 关键词规则

- 输入去掉首尾空白后为空时，显示符合当前筛选条件的全部小说。
- 连续空白视为分隔符；多个关键词采用“全部满足”规则。不同关键词可以分别命中不同字段，例如输入 `Priest 古代`，作者命中 `Priest` 且标签命中“古代”即可显示。
- 单个关键词在可搜索字段中的任意一个命中即可。中文采用连续文字包含匹配；英文不区分大小写。
- `%`、`_` 和反斜杠按普通文字处理，不能被当作 SQLite 通配符或转义符。
- 不支持正则表达式、高级搜索语法、拼音搜索、同义词扩展或自动纠错。

## 筛选规则

- 阅读状态为单选，可选“全部状态、想读、在读、读完、弃读”。
- 作品类型为单选，可选“全部类型、耽美、言情、GL、无 CP、其他”。
- 标签为多选；选择多个标签时，小说必须同时拥有全部所选标签。
- 关键词、状态、作品类型和标签之间采用“同时满足”规则。
- “清除筛选”一次清空关键词、状态、作品类型和全部标签。
- 筛选条件在用户进入小说详情再返回书架时保留；关闭并重新启动 App 后恢复默认，不新增持久化设置。

## 查询与排序

- 新增独立的 `BookSearchRepository`，由书架页面提交完整的查询对象，不让页面拼接 SQL。
- SQLite 使用参数化查询和 `EXISTS` 子查询匹配主角、标签与摘记，避免 SQL 注入，并将 `%`、`_` 和反斜杠正确转义。
- 当前书库规模使用普通索引和 `LIKE ... ESCAPE` 查询，不引入 FTS 虚拟表和新的原生依赖。未来接入 OCR 或数据量明显增长时，再评估统一全文索引。
- 查询结果仍按小说最近修改时间倒序排列，时间相同时按稳定 ID 排序，确保结果不会无故跳动。
- 一部小说即使有多条摘记或多个标签命中，也只返回一次。
- 输入关键词时进行短暂防抖，避免每输入一个字都立即发起并发查询；最终结果必须对应当前最新条件，旧查询完成后不得覆盖新查询结果。

## 匹配提示

- 书架卡片继续显示书名、作者、状态和评分，不增加常驻的阅读次数或摘记数量。
- 如果小说仅因摘记文字匹配，卡片下方显示一条“匹配摘记”摘要，帮助用户理解为什么这本书出现在结果中。
- 摘要截取第一条匹配摘记中关键词附近的短文本；过长时使用省略号。摘要只用于搜索结果展示，不修改原摘记。
- 如果书籍资料本身已经匹配，也可以不显示摘记摘要，保持书架简洁。

## 页面交互

1. 书架顶部保留一个搜索框，提示文字改为“搜索书名、作者、主角、标签或摘记”。
2. 搜索框下保留“筛选条件”和“清除筛选”。有任意条件生效时，显示当前筛选数量或明显的已筛选状态。
3. 展开筛选区域后显示阅读状态、作品类型和可搜索的完整标签列表；标签仍可多选。
4. 查询中显示轻量加载状态，但不清空上一批结果，避免输入时页面闪烁。
5. 查询成功后更新列表；搜索框输入和筛选选择保持不变。
6. 没有匹配结果时显示“没有符合条件的小说”，并提供“清除筛选”操作。

## 数据接口

```text
BookSearchFilters
  query: string
  status: BookStatus | null
  bookType: BookType | null
  tagIds: string[]

BookSearchResult
  book: Book
  matchedNoteSnippet: string | null

BookSearchRepository.search(filters: BookSearchFilters): Promise<BookSearchResult[]>
```

- `BookSearchRepository` 负责查询书籍、主角、标签和匹配摘记，并组装现有 `Book` 对象。
- `matchedNoteSnippet` 只在摘记参与匹配且需要解释结果时返回，否则为 `null`。
- 不修改现有书籍、摘记或标签数据；本功能为只读查询，不需要数据库版本升级。

## 错误与边界处理

- 查询失败时保留当前输入和筛选条件，继续显示上一批成功结果，并提示“搜索失败，请重试”。
- 快速连续输入时只接受最后一次查询结果；页面卸载后完成的查询不得更新状态。
- 已删除的摘记、标签或小说不能出现在新查询结果中。
- 同名小说分别返回，不能因书名相同而合并。
- 自定义标签、作者或摘记中包含 `%`、`_`、反斜杠、英文大小写或多余空白时仍按前述规则正确匹配。

## 暂不包含

- 图片 OCR 文字搜索、拼音或模糊纠错、联网搜索、搜索历史、热门搜索和搜索建议。
- 按评分、阅读日期或阅读次数筛选。
- 用户自定义排序、结果分组或保存筛选方案。
- 修改书架卡片的长期信息密度。

## 验收标准

- 可分别通过书名、作者、主角、中文作品类型、系统／自定义标签和摘记文字找到小说。
- 多关键词可以分别命中作者和标签，只有全部关键词满足的小说才显示。
- 状态、类型、多个标签和关键词可以同时使用；多个标签采用“全部拥有”规则。
- `%`、`_` 和反斜杠按普通文字搜索，不扩大结果范围，也不会导致查询错误。
- 摘记独有命中时显示匹配摘要，修改或删除该摘记后结果和摘要同步变化。
- 同一本小说有多条命中摘记时只显示一张书卡；同名的不同小说仍分别显示。
- 清除筛选恢复完整书架；进入详情再返回时保留条件，重启 App 后恢复默认。
- 空书架、无结果、查询中和查询失败均有清楚且不误导的状态。
- 自动化测试覆盖字段搜索、多关键词、组合筛选、特殊字符、重复行去重、摘要、查询竞态和失败保留旧结果。
- iPhone Expo Go 真机验收至少验证：输入中文和英文关键词、搜索摘记、选择两个标签、进入详情再返回、清除筛选和无结果页面。
