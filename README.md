# Novel Tracker

记录网络小说的离线 iPhone App。可以在新建时填写书名、作者、阅读状态、主角名字、作品类型、快捷标签及可选评分，也可以在详情页查看和编辑这些资料。每次阅读的日期和结果会保存在阅读历史中。

## 产品方向

先服务中文网文读者，长期目标是让不同语言的小说读者都能保存自己的私人阅读档案。新增时只填书名也能保存；弃读、重读和随手感想都属于这本书的经历。现已支持将旧清单、字段段落和“编号书目＋回复”的纯文字、UTF-8 TXT、CSV 或 XLSX 追加到书库：必须先预览、编辑并确认，重复书目和未归属原文不会静默处理。精彩片段和摘记中的本地截图可在 iPhone 专用开发版中由 Apple Vision 离线识别，识别文字可参与书名、作者、主角和摘记搜索，但不会改写摘记正文。微博链接和网页抓取仍不自动识别。现有 `.noveltracker` 文件用于本 App 的备份和整体恢复，不等同于旧记录导入或开放格式导出。最新范围见[第一版产品需求总纲](docs/superpowers/specs/2026-09-29-novel-tracker-design.md)。

## 本地开发

1. 安装 Node.js LTS、Git 和 iPhone 上的 Expo Go。
2. 让电脑和 iPhone 连接同一个 Wi-Fi。在项目目录执行 `npm.cmd ci`，然后运行 `npx.cmd expo start --lan`（Windows PowerShell 使用 `.cmd` 可避开脚本执行策略限制）。
3. 用 iPhone 扫描终端显示的二维码。如果二维码无法使用，可在 iPhone Safari 打开 `exp://电脑的局域网 IPv4 地址:8081`，再交给 Expo Go；使用 LAN 地址不需要先完成 Expo CLI 登录。
   Expo Go 只能验证不依赖自定义原生模块的功能；它会安全地跳过本地 OCR。要验证图片文字识别，需在 macOS/Xcode 或 EAS 上构建专用开发版：先安装依赖，再运行 `npx.cmd expo start --dev-client`，构建配置使用 `eas.json` 的 `development` profile。构建和安装 iPhone 版本需要可用的 Apple 签名凭据。
4. 点击“添加小说”，只填书名就能保存为“想读”；也可以直接填写作者、选择“想读／在读／读完／弃读”，并记录主角名字。主角默认显示两个输入框，也可以点“＋ 添加主角”继续增加；空白名字不会保存。
5. 选择“在读／读完／弃读”时，可在保存前编辑本次阅读的日期，格式为 `YYYY-MM-DD`；“读完／弃读”有开始和结束两项，默认都是当天。选择“读完”时，还可拖动五颗星下方的滑杆给整本书打 0.5～5 星的可选评分，每格半星；滑到最左端为未评分。点击书架上的小说进入详情，再点“编辑资料”可修改或清除评分。已评分的书改回“在读”等状态时，原评分会保留，除非手动清除。
6. 新增小说时可选一个作品类型和多个快捷标签；进入“编辑资料”可搜索完整标签库并添加自定义标签。书架的“筛选条件”可按状态、作品类型和多个标签叠加筛选，也能搜索书名、作者和主角。点击“快捷标签设置”可以调整新增页面显示的标签及其顺序，移出快捷列表不会删除小说已有标签。
7. 书架搜索框下方可以切换“最近修改”“最近读完”“最近添加”“评分从高到低”四种排序。排序会与关键词和筛选条件一起生效；最近读完只使用真实记录的完成日期，没有完成日期的书排在后面，未评分的书排在评分书后面。排序选择仅在当前打开书架时保留，重新启动后默认恢复为最近修改。
8. 书架进入“批量整理”后，可以跨搜索、筛选和排序结果按稳定书目 ID 选择多本小说；“全选当前结果”只会选择已经完成加载的当前结果。确认前可预览每本书的前后变化，并一次性添加／移除标签或统一设置作品类型；自定义标签在确认时才写入。保存使用单次事务，预览过期或保存失败会整体回滚，阅读状态、日期、评分、摘记和图片不会被批量整理修改。
9. 状态变化会自动形成阅读历史：把“读完”改为“在读”即开始下一次阅读，再改为“读完”或“弃读”即结束这次阅读，无须另按开始／结束按钮。详情页默认展示所有记录，可修改日期或确认删除误记录。旧版已读书不会被伪造日期：首刷显示“日期未记录”，可选补记；可不补记而直接开始二刷。
10. 每本书可以保存一个可选封面：可从相册选择，也可粘贴 HTTPS 图片链接下载；应用只保存本机图片，不保存网络链接。没有封面时会显示带书名的默认封面，书名过长最多显示三行。封面可在编辑资料中替换或移除，并会随 v3 备份恢复；旧 v1/v2 备份恢复后封面为空，旧备份仍可读取。
11. 详情页底部可以删除整本小说。删除前会显示书名、阅读记录、摘记、精彩片段和封面，并要求二次确认；删除后无法在应用内撤销。删除不会影响其他小说、全局标签、快捷标签或手机相册原图；删除前已经导出的备份仍可能恢复这本书，而且恢复会完整替换当前书库。
12. 用 iPhone 验收时，打开键盘输入主角 2，并试着向下滚动确认输入框没有被遮住；新建一本“读完”且评分为 4.5 星的小说，修改首刷开始／结束日期，填上作者和三个主角，并分别测试默认封面、相册封面和 HTTPS 图片链接封面。退出并重新进入 Expo Go，确认资料、封面和阅读历史仍在。再将它改为“在读”开始二刷、改为“弃读”结束二刷，检查总体评分仍在；旧已读书应显示“日期未记录”，且可以直接二刷。
13. 专用开发版可继续在前台逐张识别仍被摘记或精彩片段引用的本地图片；详情页会显示识别进度，点开图片可查看原图、识别文字和失败重试。搜索命中图片文字时，书架会标明“匹配图片文字”，点开后直接预览已核验的图片。后台会暂停队列，恢复备份时会作废旧任务并在新书库上重建索引。Expo Go、Android 和 Web 没有 Apple Vision 模块时，图片浏览和普通搜索仍可用，但不会显示“已识别”。
14. 书架的“随机想读”会从整个书库当前状态为“想读”的小说中等概率抽取，不受搜索、筛选或排序影响；抽取结果不会修改书籍数据，可以查看详情或再抽一本。没有候选书目时会显示空状态。

## 表格导入

## 截图导入

在“数据管理 → 追加旧记录”中点击“从截图导入”，一次可选择最多 20 张图片。应用会保留图片顺序；你可以继续选择、上移／下移、删除图片，并明确标记后续图片是否接上一张。每张图片都有可编辑的多行文字，解析前可以反复修正。

Expo Go 不包含项目的本地原生 OCR 模块，因此在 Expo Go 中会明确显示“本地识字不可用，可手动输入”，但多图选择、手工文字、候选预览、片段归属和事务提交都可以完整验证。自动中文识字需要安装包含 Apple Vision 模块的 iPhone 专用开发版；当前 Windows 工作区未完成该真机验证，不将它写成已通过。

截图文字只在当前导入会话中使用，不会把图片 URI 或 OCR 原文写入书籍、备份或开放格式导出。回复、时间和“共 N 条回复”等内容先进入待处理片段；只有用户明确附到摘记、设为新书或忽略后，才能确认导入。两位数日期只作为原文提示，必须在预览中输入有效的四位 `YYYY-MM-DD` 才会保存为摘记原记录日期。

在“数据管理 → 追加旧记录”中选择 CSV 或 XLSX。CSV 必须是 UTF-8（可带 BOM），支持逗号、分号和制表符分隔；不支持旧式 `.xls`。单个 CSV 不超过 1 MiB，XLSX 不超过 5 MiB、最多 1,000 个 ZIP 条目且实际或声明解压总量不超过 25 MiB；一次最多处理 500 个非空数据行、100 列。超出限制、损坏、加密或不安全的 XLSX 会被拒绝。

导入流程是“选择文件 → 选择工作表（XLSX）→ 对应列 → 导入预览”。书名列必须对应；没有用途的列必须显式确认忽略。前五行可直接修正，日期、评分、状态、作品类型和标签问题必须修正或明确跳过，错误不会静默丢弃。同一本书的多行不会自动合并成二刷；确认后才会进入现有的重复检查和事务提交。作者、主角、摘记、想看理由、阅读平台等字段为空时保持为空，未知日期保持“日期未记录”。

确认导入后会先显示“导入完成”统计页，只有事务成功才会显示。页面统计新增小说、想法、阅读记录、重读记录、五星小说、追加目标书目、跳过项和最早可靠记录日期；导入失败或取消不会显示成功页。可以从该页返回书库或打开年度回顾。

书架上的“书库概览”是只读统计：显示当前四种阅读状态数量，并按设备本地年份统计有明确结束日期的读完书籍。同一本书多次读完只计一次；跨年、未知结束日期和仅有旧版阅读次数的记录不计入“今年读完”。年度回顾中可以打开“主题回顾卡片”，按年份查看“今年二刷成功”“五星书”“弃读书”：只使用真实结束日期；五星书要求当前评分为 5 星且当年读完，二刷成功要求当年完成序号至少为 2 的读完记录，弃读书要求当年存在弃读记录。

## 备份与恢复

在书架点击“数据管理”可以选择“追加旧记录”或进入“备份与恢复”。追加旧记录只新增确认的书籍、阅读记录和摘记，不会替换现有书库；导入时日期未知会保持“日期未记录”，不会擅自填入今天。预览中的重复项可以跳过或明确选择追加摘记，原文片段需要标记后才能确认。

在书架点击“备份与恢复”，选择“生成备份”，再通过 iOS 分享面板将 `.noveltracker` 文件保存到“文件”或其他安全位置。当前备份新写 v4，同时继续读取 v1～v3；页面显示的是“上次生成备份”时间，不代表系统分享目标已确认保存。

如果只想在 App 外查看或整理数据，可在书架点击“数据管理 → 导出开放格式”。导出的 `NovelTracker-export-YYYYMMDD-HHMMSS.zip` 是一份只读副本，包含完整的 `library.json`、易读的 `books.csv`、`reading-history.csv`、`notes.csv`、`images.csv`、`README.txt` 以及 `images/` 原图目录。开放格式当前为 v2，JSON 和 `books.csv` 会保留想看理由与阅读平台；JSON 保留稳定 ID、关联和未知日期的 `null`；CSV 适合在电脑上查看，图片只打包一次并通过 ID 关联。该 ZIP 未加密，可能含私人感想和截图，请在系统分享面板中自行选择“存储到文件”等目标。开放格式导出不可直接恢复到 App；需要在 App 内整体恢复时，请使用 `.noveltracker` 备份。

选择“从备份恢复”后先检查备份时间和内容数量，再确认完整替换。恢复会覆盖当前书架中的小说、标签、阅读历史、摘记和图片；验证通过且再次确认后才开始替换。OCR 文本是可重建索引，不写入 v4 备份或开放导出 ZIP；恢复后图片文字搜索可能需要等待索引重新建立。备份可能含私人摘记和截图，请妥善保管，并定期将文件复制到安全位置。

在 iPhone Expo Go 的验收步骤：准备一本有二刷记录、至少一条摘记和共用图片的小说，导出到“文件”；修改当前书库后选取备份，核对预览再确认恢复。检查书籍、标签、阅读记录、摘记和图片关联；再选择普通 JSON 或损坏文件，确认应用拒绝恢复且原有书库仍在。取消文件选择或最终确认时应不改变数据。

删除功能验收：先进入一本测试书的详情页，点击“删除小说”并选择“取消”，确认书仍在；再重新点击并确认删除，检查它及其阅读记录、摘记、精彩片段和封面消失，另一本文字和标签仍在。重新打开 App 后确认删除结果保持。删除前的备份不会被修改；从它恢复时会按完整替换规则重新出现。

项目使用 Expo SDK 57，以配合 iPhone 上的 Expo Go 57。Windows 上可编写和运行开发服务器；iOS 实机操作由用户在自己的手机上完成。Apple Vision OCR 模块只在专用 iOS 开发版中存在，当前 Windows 工作区不能替代 Xcode 或 Apple 签名完成 Swift 编译验收。

若 LAN 二维码显示的不是电脑 Wi-Fi 地址，可在启动前设置 `$env:REACT_NATIVE_PACKAGER_HOSTNAME='电脑的局域网 IPv4 地址'`。只有需要 Expo 账号功能时才运行 `npx.cmd expo login --browser`；如果浏览器不能自动打开，可先设置 `$env:BROWSER='none'`，再手动打开终端新生成的登录链接。

## 数据提示

阅读数据保存在当前设备。删除阅读记录需要确认，删除最新一次时书籍状态可能回退。清除或卸载 Expo Go 可能会删除其中尚未导出的项目数据；请在重要变更后及时生成备份，并把备份文件保存在设备 App 数据目录之外。独立安装版将有自己的存储空间，可通过备份文件迁移记录。

## 开发验证

`npm.cmd test -- --runInBand`、`npx.cmd tsc --noEmit`、`npx.cmd expo lint --no-cache`、`npx.cmd expo-doctor`、`npx.cmd expo export --platform ios`。本地模块源码可在 Windows 上做类型和静态检查；Swift 编译、专用开发版安装和 iPhone 离线识别仍需在具备 Apple 工具链与签名凭据的环境完成。
